نحوه استفاده از فرمت JSON

  1. JSON خود را جایگذاری کنیدJSON را از یک API، یک فایل پیکربندی یا یک آموزش کپی کنید و آن را در کادر بزرگ قرار دهید.
  2. اقدامی را انتخاب کنیدقالب‌بندی را فشار دهید تا با تورفتگی قابل خواندن باشد، کوچک‌سازی را برای کوچک کردن آن به یک خط یا Validate Only برای بررسی بدون تغییر فشار دهید.
  3. در صورت وجود خطا، آن را بخوانیداگر JSON نامعتبر باشد، ابزار خطای دقیق تجزیه‌گر را با کلمات ساده نشان می‌دهد، بنابراین می‌دانید چه چیزی را باید برطرف کنید.
  4. نتیجه را کپی کنیداز کپی خروجی برای برگرداندن JSON فرمت شده یا کوچک شده به کد، پیکربندی یا ابزار API خود استفاده کنید.

JSON چیست و چرا قالب بندی اهمیت دارد

JSON، مخفف عبارت JavaScript Object Notation، رایج‌ترین روشی است که رایانه‌ها داده‌های ساختاریافته را در وب مبادله می‌کنند. APIها، فایل‌های پیکربندی و بسیاری از برنامه‌ها همگی با JSON صحبت می‌کنند، زیرا خواندن آن ساده است و تجزیه و تحلیل آن برای ماشین‌ها آسان است. یک سند JSON معتبر از اشیاء در پرانتزهای فرفری، آرایه‌ها در براکت‌های مربع، رشته‌ها در دو گیومه، اعداد و مقادیر true، false و null ساخته می‌شود. قالب‌بندی معنای داده‌ها را تغییر نمی‌دهد، اما نحوه خواندن آن برای انسان را تغییر می‌دهد. JSON Minified، با حذف تمام فضاها، برای ارسال از طریق شبکه کوچکتر و سریعتر است، به همین دلیل APIها از آن استفاده می کنند، اما خواندن یا اشکال زدایی آن تقریبا غیرممکن است. JSON زیبا، با تورفتگی دو فاصله و یک مقدار در هر خط، بزرگتر است، اما به شما امکان می دهد کاما یا یک براکت اشتباه را در چند ثانیه تشخیص دهید.

رایج ترین خطاهای JSON

  • وجود کاما یا کاما اضافی: هر مورد در یک شی یا آرایه به جز آخرین مورد نیاز به کاما دارد و کامای آخر بعد از آخرین مورد در JSON سختگیرانه مجاز نیست.
  • نقل‌قول‌های تکی به جای نقل‌قول‌های دوگانه: رشته‌های JSON باید از نقل‌قول‌های دوگانه استفاده کنند، حتی اگر کد جاوا اسکریپت اغلب نقل قول‌های تکی را مجاز می‌کند.
  • کلیدهای نقل قول نشده: کلیدهای شی باید رشته های نقل قول باشند، بنابراین {name: "Ana"} نامعتبر است و باید {"name": "Ana"} باشد.
  • نظرات: JSON اجازه کامنت را نمی دهد، بنابراین خطوطی که با // شروع می شوند حتی اگر بی ضرر به نظر برسند، تجزیه می شوند.
  • متن دنباله دار یا چندین سند: چسباندن دو شی JSON یکی پس از دیگری نامعتبر است. آنها را در یک آرایه بپیچید یا آنها را یکی یکی تعمیر کنید.

قالب‌بندی در مقابل کوچک‌سازی: زمان استفاده از هر کدام

هنگامی که در حال خواندن، اشکال زدایی یا یادگیری از JSON هستید، از قالب‌بندی استفاده کنید، زیرا تورفتگی ساختار را در یک نگاه آشکار می کند و تودرتو را آشکار می کند. زمانی که نیاز دارید JSON را در یک URL، یک فیلد پیکربندی فشرده، یک درخواست آزمایشی یا پیامی که اندازه آن مهم است و خوانایی آن مهم نیست، جایگذاری کنید از کوچک‌سازی استفاده کنید. از Validate Only زمانی استفاده کنید که فقط به پاسخ بله یا خیر نیاز دارید، به عنوان مثال قبل از ذخیره یک فایل پیکربندی، زیرا JSON را بدون جایگزین کردن متن اصلی شما بررسی می کند. در هر سه مورد، ابزار ابتدا JSON را تجزیه می کند، بنابراین یک نتیجه کوچک شده یا فرمت شده معتبر است. اگر تجزیه ناموفق باشد، به جای خروجی بی‌صدا شکسته، با خطا مواجه می‌شوید، که دقیقاً همان چیزی است که قبل از ارسال کد می‌خواهید.

حریم خصوصی و محدودیت ها

این قالب‌کننده به طور کامل در مرورگر شما اجرا می‌شود. JSON شما هرگز آپلود، ثبت یا به اشتراک گذاشته نمی‌شود، این مهم است زیرا JSON اغلب حاوی کلیدهای API، داده‌های شخصی یا پیکربندی داخلی است. هرگز اسرار را در قالب‌بندی آنلاینی که به آن اعتماد ندارید، قرار ندهید و هر کلیدی را که به‌طور تصادفی در معرض دید قرار می‌دهید بچرخانید. این ابزار پاسخ‌های معمولی API و فایل‌های پیکربندی را به راحتی مدیریت می‌کند، اما اسناد بسیار بزرگ، ده‌ها مگابایت، ممکن است در برگه مرورگر کند باشند، زیرا تجزیه و رشته‌سازی مجدد آنها حافظه را می‌گیرد. همچنین از قوانین سختگیرانه JSON پیروی می کند، بنابراین موارد اضافی به سبک جاوا اسکریپت مانند کاماهای انتهایی، نقل قول های تکی و نظرات را رد می کند، حتی اگر برخی از ابزارها آنها را به راحتی قبول کنند.

سوالات متداول (سؤالات متداول)

تفاوت قالب‌بندی و کوچک‌سازی چیست؟
فرمت تورفتگی و شکاف خط را اضافه می کند تا JSON برای انسان آسان باشد. کوچک‌سازی تمام فضاهای غیر ضروری و شکستگی خطوط را حذف می کند تا JSON تا حد امکان برای ارسال یا ذخیره کوچک باشد.
چرا JSON من با یک خطای کاما انتهایی شکست می خورد؟
Strict JSON اجازه کاما را بعد از آخرین مورد در یک شی یا آرایه نمی دهد. کاما نهایی را بردارید و JSON تجزیه خواهد شد.
آیا می توانم از نقل قول های تک در JSON استفاده کنم؟
خیر. رشته‌ها و کلیدهای JSON باید از دو نقل قول استفاده کنند. نقل قول های تک در کد جاوا اسکریپت کار می کنند، اما JSON معتبر نیستند و این ابزار به درستی آنها را رد می کند.
آیا داده های JSON من در جایی ذخیره یا ارسال می شود؟
نه. قالب‌بندی و اعتبارسنجی کاملاً در مرورگر شما اجرا می‌شود، بنابراین داده‌های شما هرگز از دستگاه شما خارج نمی‌شوند.
آیا قالب بندی داده های من را تغییر می دهد؟
نه. قالب‌بندی و کوچک‌سازی فقط فاصله‌ها و شکستگی‌های خطوط را تغییر می‌دهد. تا زمانی که JSON برای شروع معتبر باشد، مقادیر، کلیدها و ساختار دقیقاً یکسان می مانند.
