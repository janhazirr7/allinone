نحوه استفاده از مرتب‌کننده JSON

  1. JSON خود را بچسبانیدJSON را از API، فایل پیکربندی یا آموزشی کپی کنید و در کادر بزرگ بچسبانید.
  2. عملی را انتخاب کنیدروی «قالب‌بندی» بزنید تا با تورفتگی خوانا شود، «فشرده‌سازی» تا به یک خط کوچک شود، یا «فقط اعتبارسنجی» تا بدون تغییر آن بررسی شود.
  3. اگر خطایی هست آن را بخوانیداگر JSON نامعتبر باشد، ابزار خطای دقیق تجزیه‌گر را به زبان ساده نشان می‌دهد تا بدانید چه چیزی را اصلاح کنید.
  4. نتیجه را کپی کنیداز «کپی خروجی» برای بردن JSON قالب‌بندی‌شده یا فشرده‌شده به کد، پیکربندی یا ابزار API خود استفاده کنید.

JSON چیست و چرا قالب‌بندی اهمیت دارد

JSON، مخفف JavaScript Object Notation، رایج‌ترین راهی است که رایانه‌ها داده‌های ساخت‌یافته را در وب مبادله می‌کنند. APIها، فایل‌های پیکربندی و بسیاری از برنامه‌ها به JSON سخن می‌گویند، چون خواندن آن ساده و تجزیه آن برای ماشین‌ها آسان است. سند JSON معتبر از اشیایی در آکولاد، آرایه‌هایی در کروشه، رشته‌هایی در نقل‌قول دوتایی، اعداد و مقادیر true، false و null ساخته می‌شود. قالب‌بندی معنای داده را تغییر نمی‌دهد، اما آسانی خواندن آن برای انسان را تغییر می‌دهد. JSON فشرده‌شده، با حذف همه فاصله‌ها، کوچک‌تر و برای ارسال روی شبکه سریع‌تر است و به همین دلیل APIها از آن استفاده می‌کنند، اما خواندن یا اشکال‌زدایی آن تقریباً ناممکن است. JSON مرتب‌شده، با تورفتگی دوفاصله‌ای و یک مقدار در هر خط، بزرگ‌تر است اما به شما امکان می‌دهد ویرگول گمشده یا کروشه اشتباه را در چند ثانیه تشخیص دهید.

رایج‌ترین خطاهای JSON

  • ویرگول‌های گمشده یا اضافه: هر مورد در شیء یا آرایه به‌جز مورد آخر به ویرگول نیاز دارد و ویرگول پایانی پس از مورد آخر در JSON سختگیرانه مجاز نیست.
  • نقل‌قول‌های تکی به‌جای نقل‌قول‌های دوتایی: رشته‌های JSON باید از نقل‌قول دوتایی استفاده کنند، با این‌که کد JavaScript اغلب نقل‌قول‌های تکی را مجاز می‌داند.
  • کلیدهای بدون نقل‌قول: کلیدهای شیء باید رشته‌های نقل‌قول‌دار باشند، پس {name: "Ana"} نامعتبر است و باید {"name": "Ana"} باشد.
  • توضیحات: JSON اجازه توضیح نمی‌دهد، پس خط‌هایی که با // شروع می‌شوند حتی اگر بی‌ضرر به نظر برسند تجزیه را خراب می‌کنند.
  • متن پایانی یا اسناد چندتایی: چسباندن دو شیء JSON یکی پس از دیگری نامعتبر است؛ آن‌ها را در آرایه‌ای بپیچید یا یکی‌یکی اصلاح کنید.

قالب‌بندی در برابر فشرده‌سازی: هر یک را چه زمانی استفاده کنیم

وقتی JSON را می‌خوانید، اشکال‌زدایی می‌کنید یا از آن می‌آموزید از «قالب‌بندی» استفاده کنید، چون تورفتگی ساختار را در یک نگاه آشکار می‌کند و تو در تو بودن را واضح می‌کند. وقتی نیاز دارید JSON را در URL، فیلد پیکربندی فشرده، درخواست آزمایشی یا پیامی بچسبانید که اندازه اهمیت دارد و خوانایی ندارد از «فشرده‌سازی» استفاده کنید. وقتی فقط به پاسخ بله یا خیر نیاز دارید، مثلاً پیش از ذخیره فایل پیکربندی، از «فقط اعتبارسنجی» استفاده کنید، چون JSON را بدون جایگزینی متن اصلی شما بررسی می‌کند. در هر سه حالت ابزار اول JSON را تجزیه می‌کند، پس نتیجه فشرده‌شده یا قالب‌بندی‌شده تضمین می‌شود که معتبر باشد؛ اگر تجزیه شکست بخورد، به‌جای خروجی بی‌صدا خراب، خطا می‌گیرید که دقیقاً همان چیزی است که پیش از ارسال کد می‌خواهید.

حریم خصوصی و محدودیت‌ها

این مرتب‌کننده کاملاً در مرورگر شما اجرا می‌شود. JSON شما هرگز بارگذاری، ثبت یا به اشتراک گذاشته نمی‌شود که اهمیت دارد، چون JSON اغلب حاوی کلیدهای API، داده شخصی یا پیکربندی داخلی است. هرگز رازها را در مرتب‌کننده آنلاینی که به آن اعتماد ندارید نچسبانید و هر کلیدی را که به‌طور تصادفی افشا کردید بچرخانید. این ابزار پاسخ‌های معمول API و فایل‌های پیکربندی را به‌راحتی پوشش می‌دهد، اما اسناد بسیار بزرگ، ده‌ها مگابایت، ممکن است در زبانه مرورگر کند باشند، چون تجزیه و بازسازی رشته‌ای آن‌ها حافظه می‌برد. همچنین از قوانین سختگیرانه JSON پیروی می‌کند، پس موارد اضافه به سبک JavaScript مانند ویرگول‌های پایانی، نقل‌قول‌های تکی و توضیحات را رد می‌کند، با این‌که برخی ابزارها آن‌ها را با تساهل می‌پذیرند.

پرسش‌های پرتکرار (FAQs)

تفاوت قالب‌بندی و فشرده‌سازی چیست؟
قالب‌بندی تورفتگی و شکست خطوط اضافه می‌کند تا JSON برای انسان‌ها آسان خوانده شود. فشرده‌سازی همه فاصله‌ها و شکست خطوط غیرضروری را حذف می‌کند تا JSON برای ارسال یا ذخیره تا حد ممکن کوچک باشد.
چرا JSON من با خطای ویرگول پایانی شکست می‌خورد؟
JSON سختگیرانه ویرگولی پس از مورد آخر در شیء یا آرایه را مجاز نمی‌داند. آن ویرگول نهایی را حذف کنید و JSON تجزیه می‌شود.
آیا می‌توانم در JSON از نقل‌قول تکی استفاده کنم؟
خیر. رشته‌ها و کلیدهای JSON باید از نقل‌قول دوتایی استفاده کنند. نقل‌قول‌های تکی در کد JavaScript کار می‌کنند، اما JSON معتبر نیستند و این ابزار به‌درستی آن‌ها را رد می‌کند.
آیا داده JSON من جایی ذخیره یا فرستاده می‌شود؟
خیر. قالب‌بندی و اعتبارسنجی کاملاً در مرورگر شما اجرا می‌شوند، پس داده شما هرگز از دستگاه شما خارج نمی‌شود.
آیا قالب‌بندی داده مرا تغییر می‌دهد؟
خیر. قالب‌بندی و فشرده‌سازی فقط فاصله‌گذاری و شکست خطوط را تغییر می‌دهند. مقادیر، کلیدها و ساختار دقیقاً همان‌طور می‌مانند، تا وقتی که JSON از آغاز معتبر بوده باشد.
