JSON 포맷터 사용 방법

  1. JSON 붙여넣기API, 설정 파일, 튜토리얼에서 JSON을 복사해 큰 상자에 붙여넣으세요.
  2. 동작 선택'서식 지정'을 눌러 들여쓰기로 읽기 쉽게 만들거나, '압축'을 눌러 한 줄로 줄이거나, '검증만'을 눌러 바꾸지 않고 확인하세요.
  3. 오류가 있으면 읽기JSON이 유효하지 않으면, 도구가 파서의 정확한 오류를 쉬운 말로 보여주므로 무엇을 고쳐야 할지 알 수 있습니다.
  4. 결과 복사하기'출력 복사'를 이용해 서식이 적용되거나 축소된 JSON을 코드, 설정, API 도구로 가져가세요.

JSON이란 무엇이고 서식이 왜 중요한가

JSON은 JavaScript Object Notation의 줄임말로, 컴퓨터가 웹에서 구조화된 데이터를 교환하는 가장 흔한 방식입니다. API, 설정 파일, 많은 앱이 모두 JSON을 사용하는데, 사람이 읽기 쉽고 기계가 파싱하기 쉽기 때문입니다. 유효한 JSON 문서는 중괄호 안의 객체, 대괄호 안의 배열, 큰따옴표 안의 문자열, 숫자, 그리고 true, false, null 값으로 구성됩니다. 서식을 바꾸어도 데이터의 의미는 바뀌지 않지만, 사람이 읽기가 얼마나 쉬운지는 바뀝니다. 모든 공백을 제거한 압축 JSON은 더 작고 네트워크로 보내기 빠르므로 API가 이를 사용하지만, 읽거나 디버깅하기는 거의 불가능합니다. 2칸 들여쓰기와 한 줄에 하나의 값을 적용한 보기 좋은 JSON은 더 크지만, 빠진 쉼표나 잘못된 괄호를 몇 초 만에 찾을 수 있게 해줍니다.

가장 흔한 JSON 오류

  • 빠지거나 여분의 쉼표: 객체나 배열의 마지막 항목을 제외한 모든 항목에는 쉼표가 필요하고, 마지막 항목 뒤의 후행 쉼표는 엄격한 JSON에서 허용되지 않습니다.
  • 큰따옴표 대신 작은따옴표: 자바스크립트 코드에서는 작은따옴표가 허용되는 경우가 많지만, JSON 문자열은 큰따옴표를 사용해야 합니다.
  • 따옴표 없는 키: 객체 키는 따옴표로 묶인 문자열이어야 하므로, {name: "Ana"}는 유효하지 않고 {"name": "Ana"}여야 합니다.
  • 주석: JSON은 주석을 허용하지 않으므로, //로 시작하는 행은 무해해 보여도 파싱을 깨뜨립니다.
  • 후행 텍스트 또는 여러 문서: 두 개의 JSON 객체를 연달아 붙여넣는 것은 유효하지 않습니다. 배열로 감싸거나 한 번에 하나씩 수정하세요.

서식 지정과 압축: 각각 언제 사용할 것인가

JSON을 읽거나, 디버깅하거나, 배우고 있을 때는 '서식 적용'을 사용하세요. 들여쓰기가 구조를 한눈에 드러내고 중첩을 명확히 하기 때문입니다. JSON을 URL, 간결한 설정 필드, 테스트 요청, 크기가 중요하고 가독성이 중요하지 않은 메시지에 붙여넣어야 할 때는 '축소'를 사용하세요. 설정 파일을 저장하기 전처럼 예/아니요 답만 필요할 때는 '유효성 검사만'을 사용하세요. 원본 텍스트를 바꾸지 않고 JSON을 검사하기 때문입니다. 세 경우 모두 도구가 먼저 JSON을 파싱하므로, 축소되거나 서식이 적용된 결과는 유효함이 보장됩니다. 파싱에 실패하면 조용히 깨진 출력 대신 오류를 받게 되며, 이는 코드를 배포하기 전에 정확히 원하는 동작입니다.

개인정보 보호와 한계

이 포맷터는 전적으로 브라우저에서 실행됩니다. JSON이 업로드되거나, 기록되거나, 공유되지 않습니다. 이는 중요합니다. JSON에는 API 키, 개인 데이터, 내부 설정이 포함되는 경우가 많기 때문입니다. 신뢰하지 않는 온라인 포맷터에는 비밀을 절대 붙여넣지 말고, 실수로 노출한 키는 교체하세요. 이 도구는 일반적인 API 응답과 설정 파일을 쉽게 처리하지만, 수십 메가바이트에 달하는 극도로 큰 문서는 파싱과 다시 문자열화하는 데 메모리가 들므로 브라우저 탭에서 느릴 수 있습니다. 또한 엄격한 JSON 규칙을 따르므로, 일부 도구가 느슨하게 받아들이는 후행 쉼표, 작은따옴표, 주석 같은 자바스크립트식 추가 요소를 거부합니다.

자주 묻는 질문(FAQ)

서식 적용과 축소의 차이는?
서식 지정은 들여쓰기와 줄 바꿈을 추가해 JSON을 사람이 읽기 쉽게 만듭니다. 압축은 불필요한 공백과 줄 바꿈을 모두 제거해 JSON을 전송하거나 저장하기에 최대한 작게 만듭니다.
내 JSON이 후행 쉼표 오류로 실패하는 이유는?
엄격한 JSON에서는 객체나 배열의 마지막 항목 뒤에 쉼표를 허용하지 않습니다. 마지막 쉼표를 제거하면 JSON이 파싱됩니다.
JSON에서 작은따옴표를 사용할 수 있나요?
아니요. JSON 문자열과 키는 큰따옴표를 사용해야 합니다. 작은따옴표는 자바스크립트 코드에서는 동작하지만 유효한 JSON이 아니므로, 이 도구는 이를 올바르게 거부합니다.
내 JSON 데이터가 저장되거나 전송되나요?
아니요. 서식 지정과 검증은 전적으로 브라우저에서 이루어지므로, 데이터가 기기를 떠나지 않습니다.
서식을 바꾸면 데이터가 바뀌나요?
아니요. 서식 지정과 압축은 공백과 줄 바꿈만 바꿉니다. JSON이 애초에 유효했다면 값, 키, 구조는 정확히 그대로 유지됩니다.
