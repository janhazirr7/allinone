JSON 포맷터를 사용하는 방법

  1. JSON을 붙여넣으세요.API, 구성 파일 또는 튜토리얼에서 JSON을 복사하여 큰 상자에 붙여넣습니다.
  2. 작업을 선택하세요들여쓰기를 해서 읽을 수 있게 하려면 Format을 누르고, 한 줄로 줄이려면 Minify를 누르고, 변경하지 않고 확인하려면 Validate Only를 누르세요.
  3. 오류가 있으면 읽어보세요.JSON이 유효하지 않은 경우 도구는 파서의 정확한 오류를 일반 단어로 표시하므로 무엇을 수정해야 할지 알 수 있습니다.
  4. 결과 복사출력 복사를 사용하여 형식화되거나 축소된 JSON을 코드, 구성 또는 API 도구로 다시 가져옵니다.

JSON이 무엇이며 형식이 중요한 이유

JavaScript Object Notation의 약자인 JSON은 컴퓨터가 웹에서 구조화된 데이터를 교환하는 가장 일반적인 방법입니다. API, 구성 파일 및 많은 앱은 읽기 쉽고 기계에서 구문 분석하기 쉽기 때문에 모두 JSON을 사용합니다. 유효한 JSON 문서는 중괄호 안의 개체, 대괄호 안의 배열, 큰따옴표 안의 문자열, 숫자 및 true, false 및 null 값으로 구성됩니다. 형식을 지정해도 데이터의 의미는 바뀌지 않지만 사람이 읽기 쉬운 정도가 달라집니다. 모든 공백을 제거한 축소된 JSON은 네트워크를 통해 전송하기에 더 작고 빠르기 때문에 API가 이를 사용하지만 읽거나 디버그하는 것은 거의 불가능합니다. 두 개의 공백 들여쓰기와 한 줄에 하나의 값을 사용하는 멋진 JSON은 더 크지만 누락된 쉼표나 잘못된 대괄호를 몇 초 안에 찾아낼 수 있습니다.

가장 일반적인 JSON 오류

  • 쉼표 누락 또는 추가: 마지막 항목을 제외한 객체 또는 배열의 모든 항목에는 쉼표가 필요하며 엄격한 JSON에서는 마지막 항목 뒤의 후행 쉼표가 허용되지 않습니다.
  • 큰따옴표 대신 작은따옴표: JavaScript 코드에서 작은따옴표를 허용하는 경우가 많더라도 JSON 문자열은 큰따옴표를 사용해야 합니다.
  • 인용되지 않은 키: 객체 키는 인용된 문자열이어야 하므로 {name: "Ana"}는 유효하지 않으며 {"name": "Ana"}여야 합니다.
  • 주석: JSON은 주석을 허용하지 않으므로 //로 시작하는 줄은 무해해 보이더라도 구문 분석을 중단합니다.
  • 후행 텍스트 또는 여러 문서: 두 개의 JSON 개체를 차례로 붙여넣는 것은 유효하지 않습니다. 배열로 감싸거나 한 번에 하나씩 수정하세요.

서식 지정과 축소: 각 항목을 언제 사용해야 할까요?

들여쓰기를 통해 구조를 한 눈에 알 수 있고 중첩이 명확해지기 때문에 JSON을 읽거나 디버깅하거나 학습할 때 형식을 사용하세요. 크기는 중요하지만 가독성은 중요하지 않은 URL, 압축 구성 필드, 테스트 요청 또는 메시지에 JSON을 붙여넣어야 하는 경우 Minify를 사용하세요. 구성 파일을 저장하기 전과 같이 예 또는 아니요 대답만 필요한 경우에만 유효성 검사를 사용하세요. 원본 텍스트를 바꾸지 않고 JSON을 확인하기 때문입니다. 세 가지 경우 모두 도구는 먼저 JSON을 구문 분석하므로 축소되거나 형식화된 결과의 유효성이 보장됩니다. 구문 분석에 실패하면 소리 없이 출력이 중단되는 대신 오류가 발생합니다. 이는 코드를 출시하기 전에 정확히 원하는 것입니다.

개인 정보 보호 및 제한

이 포맷터는 브라우저에서 완전히 실행됩니다. JSON은 업로드, 기록 또는 공유되지 않습니다. JSON에는 API 키, 개인 데이터 또는 내부 구성이 포함되는 경우가 많기 때문에 이는 중요합니다. 신뢰할 수 없는 온라인 포맷터에 비밀을 붙여넣지 말고 실수로 노출된 키를 순환시키십시오. 이 도구는 일반적인 API 응답 및 구성 파일을 쉽게 처리하지만 수십 메가바이트에 달하는 매우 큰 문서는 구문 분석 및 다시 문자열화하는 데 메모리가 필요하기 때문에 브라우저 탭에서 속도가 느려질 수 있습니다. 또한 엄격한 JSON 규칙을 따르므로 일부 도구에서는 느슨하게 허용하더라도 후행 쉼표, 작은따옴표 및 주석과 같은 JavaScript 스타일 추가 항목을 거부합니다.

자주 묻는 질문(FAQ)

포맷과 축소의 차이점은 무엇입니까?
형식에 들여쓰기와 줄 바꿈이 추가되어 JSON이 사람이 쉽게 읽을 수 있습니다. Minify는 불필요한 공백과 줄 바꿈을 모두 제거하여 JSON을 전송하거나 저장하기에 최대한 작게 만듭니다.
JSON이 후행 쉼표 오류로 인해 실패하는 이유는 무엇입니까?
엄격한 JSON은 객체 또는 배열의 마지막 항목 뒤에 쉼표를 허용하지 않습니다. 마지막 쉼표를 제거하면 JSON이 구문 분석됩니다.
JSON에서 작은따옴표를 사용할 수 있나요?
아니요. JSON 문자열과 키에는 큰따옴표를 사용해야 합니다. 작은따옴표는 JavaScript 코드에서 작동하지만 유효한 JSON이 아니므로 이 도구는 이를 올바르게 거부합니다.
내 JSON 데이터가 어디에 저장되거나 전송되나요?
아니요. 형식 지정 및 유효성 검사는 전적으로 브라우저에서 실행되므로 데이터가 장치 외부로 유출되지 않습니다.
서식을 지정하면 데이터가 변경되나요?
아니요. 서식을 지정하고 축소하면 간격과 줄 바꿈만 변경됩니다. JSON이 처음부터 유효한 한 값, 키 및 구조는 정확히 동일하게 유지됩니다.
