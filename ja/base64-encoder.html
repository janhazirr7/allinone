Base64 エンコーダの使用方法

  1. テキストを入力してくださいプレーン テキストを入力または貼り付けてエンコードするか、Base64 文字列を貼り付けてデコードします。
  2. エンコードまたはデコードを選択しますエンコードを押してテキストを Base64 に変換するか、デコードを押して Base64 を読み取り可能なテキストに戻します。
  3. エラーがある場合は確認してください無効な Base64 では、空白または文字化けした結果の代わりに、問題を説明するわかりやすいエラーが表示されます。
  4. 結果をコピーする出力のコピーを使用して、結果を電子メール、構成ファイル、API リクエスト、またはメッセージに取り込みます。

Base64 とは何か、そしてなぜ存在するのか

Base64 は、大文字と小文字、数字、プラスとスラッシュ、末尾のパディングとして等号を含む 64 個の安全な文字のみを使用して、テキスト、画像、ファイルなどのバイトを表す方法です。コンピュータは多くの場合、電子メール ヘッダー、Web アドレス、JSON フィールド、構成ファイルなどのプレーン テキストのみを安全に処理するシステムを通じてバイナリ データを送信する必要があります。これらの場所にある生のバイトは破損したり、誤読されたり、拒否されたりする可能性があるため、Base64 はそれらを変更されずに残るテキストに変換します。トレードオフはサイズです。3 バイトが 4 文字になるため、Base64 出力は元のデータより約 3 分の 1 大きくなります。これは、トークン、小さな画像、短い文字列には許容されますが、非常に大きなファイルの場合は無駄です。そのため、Base64 はストリーミング ビデオや大規模なダウンロードには使用されません。

Unicode に特別な注意が必要な理由

単純な Base64 ツールによくあるバグは、英語以外のテキストで機能しなくなることです。古いブラウザ機能 btoa および atob はラテン文字のみを処理するため、カフェなどの単語、ウルドゥー語またはギリシャ語の名前、または絵文字によってエラーや文字化けが発生する可能性があります。このツールは、最初に TextEncoder を使用してテキストを UTF-8 バイトに変換し、それらのバイトをエンコードし、デコード時に TextDecoder を使用してプロセスを逆にすることで、そのバグを完全に回避します。つまり、Hola、Καλημέρα、مرحبا、笑顔の絵文字はすべて正しく往復し、エンコードして結果をデコードすると、元のテキストが正確に返されます。別のツールでアクセント付きテキストや非ラテン語テキストの壊れ文字が表示される場合は、ほぼ確実に、UTF-8 処理を行わずに裸の btoa と atob が使用されているため、このツールのような Unicode セーフ ツールに切り替える必要があります。

一般的な使用法とセキュリティ警告

  • データ URL: 小さな画像やアイコンは、Base64 として Web ページに直接埋め込まれることが多いため、ページに個別の画像ファイルは必要ありません。
  • API トークンと基本認証: ユーザー名、パスワード、トークンはヘッダー内で Base64 でエンコードされる場合がありますが、これは暗号化ではなく、常に HTTPS 経由で送信される必要があります。
  • 電子メールの添付ファイル: 電子メール システムは添付ファイルを Base64 でエンコードするため、バイナリ ファイルはテキスト専用のメール サーバーを通過できます。
  • 構成とテスト: 開発者は短い文字列をエンコードして API をテストし、小さな BLOB を JSON に保存し、特殊文字を気にせずに値を比較します。

プライバシーと制限

Base64 は暗号化ではなくエンコードです。 Base64 文字列を見た人は誰でも数秒で解読できるため、パスワード、秘密キー、または個人情報を隠すために使用したり、安全なものとして扱ったりしないでください。このツールは完全にブラウザ内で実行されるため、テキストがアップロードまたは保存されることはありませんが、出力自体は共有する相手であれば誰でも読むことができます。このツールは、標準の Base64 と、プラスとスラッシュの代わりにマイナスとアンダースコアを使用する URL セーフなバリアントを受け入れ、改行とパディングの欠落を許容するため、電子メールからコピーされた文字列を許容します。非常に大きな入力はブラウザ タブでは遅くなる可能性があるため、数メガバイトのファイルの場合は代わりにデスクトップ ツールを使用してください。

よくある質問 (FAQ)

Base64暗号化ですか?
いいえ、Base64 はエンコードのみであり、形式を元に戻すことができます。 Base64 文字列は誰でも即座にデコードできるため、パスワードや秘密を隠すために使用してはなりません。
一部の Base64 ツールでアクセント付きテキストが壊れるのはなぜですか?
これらのツールは、ラテン文字のみを処理する、裸の btoa と atob を使用します。このツールは最初にテキストを UTF-8 バイトに変換するため、アクセント付き文字、ギリシャ語、ウルドゥー語、絵文字はすべて正しく機能します。
Base64 出力が私のテキストより長いのはなぜですか?
Base64 は 3 バイトごとに 4 文字に変換するため、出力は約 33% 大きくなります。これは、テキストのみのシステムに対してバイナリ データを安全にするための通常の代償です。
最後の等号は何のためにあるのでしょうか？
等号はパディングです。入力長が 3 の倍数ではない場合、最後のグループは 4 文字になるため、デコーダはデータがどこで終わるかを正確に認識します。
私のテキストはサーバーに送信されますか?
いいえ。エンコードとデコードは完全にブラウザ内で実行され、入力した内容はデバイスから送信されません。
