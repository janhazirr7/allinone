Как использовать форматтер JSON

  1. Вставьте свой JSONСкопируйте JSON из API, файла конфигурации или руководства и вставьте его в большое поле.
  2. Выберите действиеНажмите «Формат», чтобы сделать его читабельным с отступами, «Свернуть», чтобы сжать его до одной строки, или «Только проверить», чтобы проверить его, не изменяя.
  3. Прочтите ошибку, если она есть.Если JSON недействителен, инструмент отображает точную ошибку синтаксического анализатора простыми словами, чтобы вы знали, что исправить.
  4. Скопируйте результатИспользуйте Copy Output, чтобы вернуть отформатированный или минимизированный JSON в ваш код, конфигурацию или инструмент API.

Что такое JSON и почему форматирование имеет значение

JSON, сокращение от JavaScript Object Notation, — это наиболее распространенный способ обмена компьютерами структурированных данных в Интернете. API, файлы конфигурации и многие приложения поддерживают формат JSON, поскольку его легко читать и легко анализировать на машинах. Действительный документ JSON состоит из объектов в фигурных скобках, массивов в квадратных скобках, строк в двойных кавычках, чисел и значений true, false и null. Форматирование не меняет значения данных, но меняет то, насколько легко их читать человеку. Минимизированный JSON, в котором удалены все пробелы, меньше по размеру и быстрее пересылается по сети, поэтому его используют API, но его практически невозможно читать или отлаживать. Украшенный JSON с отступом в два пробела и одним значением в строке больше, но позволяет за секунды обнаружить пропущенную запятую или неправильную скобку.

Наиболее распространенные ошибки JSON

  • Отсутствующие или лишние запятые: каждый элемент в объекте или массиве, кроме последнего, нуждается в запятой, а конечная запятая после последнего элемента не допускается в строгом JSON.
  • Одинарные кавычки вместо двойных: строки JSON должны использовать двойные кавычки, хотя код JavaScript часто допускает одинарные кавычки.
  • Ключи без кавычек: ключи объекта должны быть строками в кавычках, поэтому {name: "Ana"} недопустимо и должно быть {"name": "Ana"}.
  • Комментарии: JSON не допускает комментариев, поэтому строки, начинающиеся с //, нарушат синтаксический анализ, даже если они выглядят безобидными.
  • Завершающий текст или несколько документов: вставка двух объектов JSON один за другим недействительна; оберните их в массив или исправьте по одному.

Форматирование и минимизация: когда использовать каждое из них

Используйте формат при чтении, отладке или изучении JSON, поскольку отступы сразу раскрывают структуру и делают вложенность очевидной. Используйте Minify, когда вам нужно вставить JSON в URL-адрес, компактное поле конфигурации, тестовый запрос или сообщение, где размер имеет значение, а читаемость — нет. Используйте «Проверить только», когда вам нужен только ответ «да» или «нет», например, перед сохранением файла конфигурации, поскольку он проверяет JSON без замены исходного текста. Во всех трех случаях инструмент сначала анализирует JSON, поэтому минимизированный или отформатированный результат гарантированно будет действительным; если синтаксический анализ завершается неудачей, вы получаете ошибку вместо молчаливо нарушенного вывода, а это именно то, что вам нужно перед отправкой кода.

Конфиденциальность и ограничения

Этот форматтер полностью работает в вашем браузере. Ваш JSON никогда не загружается, не регистрируется и не передается другим, что важно, поскольку JSON часто содержит ключи API, личные данные или внутреннюю конфигурацию. Никогда не вставляйте секреты в онлайн-форматеры, которым вы не доверяете, и не меняйте любой ключ, который вы случайно открыли. Инструмент легко обрабатывает типичные ответы API и файлы конфигурации, но чрезвычайно большие документы (десятки мегабайт) могут работать медленно на вкладке браузера, поскольку их анализ и повторная строковая обработка занимают память. Он также следует строгим правилам JSON, поэтому отклоняет дополнительные элементы в стиле JavaScript, такие как конечные запятые, одинарные кавычки и комментарии, хотя некоторые инструменты принимают их свободно.

Часто задаваемые вопросы (FAQ)

В чем разница между форматированием и минимизацией?
Формат добавляет отступы и разрывы строк, поэтому JSON легко читается людьми. Minify удаляет все ненужные пробелы и разрывы строк, поэтому JSON становится как можно меньшим для отправки или хранения.
Почему мой JSON завершается ошибкой с запятой?
Строгий JSON не допускает использования запятой после последнего элемента объекта или массива. Удалите последнюю запятую, и JSON будет проанализирован.
Могу ли я использовать одинарные кавычки в JSON?
Нет. Строки и ключи JSON должны заключаться в двойные кавычки. Одинарные кавычки работают в коде JavaScript, но они не являются допустимым JSON, и этот инструмент их правильно отклонит.
Мои данные JSON хранятся или отправляются куда-либо?
Нет. Форматирование и проверка полностью выполняются в вашем браузере, поэтому ваши данные никогда не покидают ваше устройство.
Изменяет ли форматирование мои данные?
Нет. Форматирование и минимизация изменяют только интервалы и разрывы строк. Значения, ключи и структура остаются прежними, пока JSON был действителен с самого начала.
