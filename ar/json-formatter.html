كيفية استخدام منسق JSON

  1. الصق JSON الخاص بكانسخ JSON من واجهة برمجة تطبيقات أو ملف إعدادات أو درس تعليمي والصقه في الصندوق الكبير.
  2. اختر إجراءًاضغط «تنسيق» لجعله مقروءًا بالمسافات البادئة، أو «تصغير» لتصغيره إلى سطر واحد، أو «تحقق فقط» للتحقق منه دون تغييره.
  3. اقرأ الخطأ إن وُجدإذا كان JSON غير صالح، تعرض الأداة الخطأ الدقيق من المحلل بلغة بسيطة، فتعرف ما يجب إصلاحه.
  4. انسخ النتيجةاستخدم «نسخ المخرجات» لأخذ JSON المنسق أو المصغّر إلى كودك أو ملف إعداداتك أو أداة واجهة برمجة التطبيقات.

ما هو JSON ولماذا يهم التنسيق

JSON، وهو اختصار لـ JavaScript Object Notation، هو الطريقة الأكثر شيوعًا لتبادل الحواسيب للبيانات المنظمة على الويب. وتتحدث واجهات برمجة التطبيقات وملفات الإعدادات وكثير من التطبيقات JSON لأنه سهل القراءة وسهل التحليل للآلات. ويُبنى مستند JSON صالح من كائنات بين قوسين معقوفين {}، ومصفوفات بين قوسين مربعين []، وسلاسل بين علامتي اقتباس مزدوجتين، وأرقام، والقيم true وfalse وnull. ولا يغيّر التنسيق معنى البيانات، لكنه يغيّر مدى سهولة قراءتها على الإنسان. فـ JSON المصغّر، مع إزالة كل المسافات، أصغر وأسرع إرسالًا عبر الشبكة، ولهذا تستخدمه واجهات برمجة التطبيقات، لكن قراءته أو تصحيحه شبه مستحيلة. أما JSON المجمّل، بمسافة بادئة من مسافتين وقيمة واحدة في كل سطر، فأكبر لكنه يتيح لك اكتشاف فاصلة مفقودة أو قوس خاطئ في ثوانٍ.

أخطاء JSON الأكثر شيوعًا

  • فواصل مفقودة أو زائدة: كل عنصر في كائن أو مصفوفة عدا الأخير يحتاج فاصلة، والفاصلة المتأخرة بعد العنصر الأخير غير مسموح بها في JSON الصارم.
  • علامات اقتباس مفردة بدل مزدوجة: سلاسل JSON يجب أن تستخدم علامات اقتباس مزدوجة، حتى لو كان كود JavaScript يسمح غالبًا بالمفردة.
  • مفاتيح غير مقتبسة: مفاتيح الكائنات يجب أن تكون سلاسل مقتبسة، لذا فإن {name: "Ana"} غير صالح ويجب أن يكون {"name": "Ana"}.
  • التعليقات: JSON لا يسمح بالتعليقات، لذا فإن السطور التي تبدأ بـ // ستكسر التحليل حتى لو بدت غير ضارة.
  • نص متأخر أو مستندات متعددة: لصق كائني JSON أحدهما بعد الآخر غير صالح؛ غلّفهما في مصفوفة أو أصلحهما واحدًا تلو الآخر.

التنسيق مقابل التصغير: متى تستخدم كلًا منهما

استخدم «تنسيق» عندما تقرأ JSON أو تصححه أو تتعلم منه، لأن المسافات البادئة تكشف البنية بنظرة وتجعل التداخل واضحًا. واستخدم «تصغير» عندما تحتاج لصق JSON في رابط أو حقل إعدادات مضغوط أو طلب اختبار أو رسالة حيث يهم الحجم ولا تهم القراءة. واستخدم «تحقق فقط» عندما تحتاج إجابة بنعم أو لا فقط، مثلًا قبل حفظ ملف إعدادات، لأنه يتحقق من JSON دون استبدال نصك الأصلي. وفي الحالات الثلاث تحلّل الأداة JSON أولًا، فنتيجة مصغّرة أو منسقة مضمونة الصحة؛ وإذا فشل التحليل، تحصل على خطأ بدل مخرجات معطوبة بصمت، وهو بالضبط ما تريده قبل شحن الكود.

الخصوصية والحدود

يعمل هذا المنسق بالكامل في متصفحك. ولا يُرفع JSON الخاص بك أو يُسجَّل أو يُشارك أبدًا، وهو ما يهم لأن JSON غالبًا ما يحتوي مفاتيح واجهات برمجة تطبيقات أو بيانات شخصية أو إعدادات داخلية. ولا تلصق أبدًا أسرارًا في أي منسق عبر الإنترنت لا تثق به، وبدّل أي مفتاح تكشفه بالخطأ. وتتعامل الأداة مع استجابات واجهات برمجة التطبيقات وملفات الإعدادات النموذجية بسهولة، لكن المستندات الضخمة جدًا، بعشرات الميغابايت، قد تكون بطيئة في تبويب متصفح لأن التحليل وإعادة التحويل إلى سلسلة يستهلكان ذاكرة. وهي تتبع أيضًا قواعد JSON الصارمة، فترفض إضافات على غرار JavaScript مثل الفواصل المتأخرة وعلامات الاقتباس المفردة والتعليقات، حتى لو قبلتها بعض الأدوات بتساهل.

الأسئلة الشائعة

ما الفرق بين التنسيق والتصغير؟
يضيف التنسيق مسافات بادئة وفواصل أسطر كي يسهل على البشر قراءة JSON. ويزيل التصغير كل المسافات وفواصل الأسطر غير الضرورية كي يكون JSON صغيرًا قدر الإمكان للإرسال أو التخزين.
لماذا يفشل JSON الخاص بي بخطأ فاصلة متأخرة؟
JSON الصارم لا يسمح بفاصلة بعد العنصر الأخير في كائن أو مصفوفة. أزل تلك الفاصلة الأخيرة وسيُحلَّل JSON.
هل يمكنني استخدام علامات اقتباس مفردة في JSON؟
لا. سلاسل JSON ومفاتيحه يجب أن تستخدم علامات اقتباس مزدوجة. وتعمل المفردة في كود JavaScript، لكنها ليست JSON صالحًا وسترفضها هذه الأداة على نحو صحيح.
هل تُخزَّن بيانات JSON الخاصة بي أو تُرسل إلى أي مكان؟
لا. يعمل التنسيق والتحقق بالكامل في متصفحك، فلا تغادر بياناتك جهازك أبدًا.
هل يغيّر التنسيق بياناتي؟
لا. يغيّر التنسيق والتصغير المسافات وفواصل الأسطر فقط. وتبقى القيم والمفاتيح والبنية كما هي بالضبط، ما دام JSON صالحًا منذ البداية.
