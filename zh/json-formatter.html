什么是 JSON 以及格式化为什么重要

JSON（JavaScript Object Notation 的简称）是计算机在网络上交换结构化数据最常见的方式。API、配置文件和许多应用都使用 JSON，因为它简单易读、易于机器解析。一个有效的 JSON 文档由花括号中的对象、方括号中的数组、双引号中的字符串、数字以及 true、false 和 null 这些值构成。格式化不会改变数据的含义，但会改变人类阅读的难易程度。压缩后的 JSON 删除了所有空格，更小、通过网络发送更快，这就是 API 使用它的原因，但它几乎不可能阅读或调试。美化后的 JSON 使用两格缩进、每行一个值，虽然更大，但能让你在几秒钟内发现缺失的逗号或错误的括号。

最常见的 JSON 错误

  • 缺失或多余的逗号：对象或数组中除最后一项外的每一项都需要逗号，而最后一项后面的尾随逗号在严格的 JSON 中是不允许的。
  • 单引号而不是双引号：JSON 字符串必须使用双引号，即使 JavaScript 代码常常允许单引号。
  • 未加引号的键：对象键必须是带引号的字符串，所以 {name: "Ana"} 是无效的，必须是 {"name": "Ana"}。
  • 注释：JSON 不允许注释，所以以 // 开头的行即使看起来无害也会破坏解析。
  • 尾随文本或多个文档：连续粘贴两个 JSON 对象是无效的；把它们包在一个数组中，或者一次修复一个。

格式化与压缩：何时使用哪一个

阅读、调试或学习 JSON 时使用“格式化”，因为缩进能一眼揭示结构、让嵌套一目了然。需要把 JSON 粘贴到 URL、紧凑的配置字段、测试请求或消息中时使用“压缩”，因为此时大小重要、可读性不重要。只需要是或否的答案时使用“仅验证”，例如保存配置文件之前，因为它会在不替换你原文的情况下检查 JSON。在这三种情况下，工具都会先解析 JSON，所以压缩或格式化的结果保证是有效的；如果解析失败，你会得到一个错误，而不是悄悄损坏的输出，这正是发布代码之前想要的。

隐私和限制

本格式化工具完全在你的浏览器中运行。你的 JSON 绝不会被上传、记录或分享，这很重要，因为 JSON 常常包含 API 密钥、个人数据或内部配置。永远不要把机密粘贴到你不信任的任何在线格式化工具中，并轮换任何你不小心泄露的密钥。工具可以轻松处理典型的 API 响应和配置文件，但非常大的文档（几十兆字节）在浏览器标签页中可能会变慢，因为解析和重新序列化它们需要内存。它还遵循严格的 JSON 规则，所以会拒绝 JavaScript 风格的额外内容，如尾随逗号、单引号和注释，即使有些工具宽松地接受它们。

常见问题

格式化和压缩有什么区别？
格式化会添加缩进和换行，让 JSON 易于人类阅读。压缩会删除所有不必要的空格和换行，让 JSON 尽可能小，便于发送或存储。
为什么我的 JSON 会因尾随逗号错误而失败？
严格的 JSON 不允许在对象或数组最后一项后面加逗号。删除最后那个逗号，JSON 就能解析了。
我可以在 JSON 中使用单引号吗？
不可以。JSON 字符串和键必须使用双引号。单引号在 JavaScript 代码中可行，但在 JSON 中无效，本工具会正确地拒绝它们。
我的 JSON 数据会被存储或发送到别处吗？
不会。格式化和验证完全在你的浏览器中运行，所以你的数据绝不会离开你的设备。
格式化会改变我的数据吗？
不会。格式化和压缩只改变空格和换行。只要 JSON 一开始就是有效的，值、键和结构就保持完全相同。
