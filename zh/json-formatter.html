JSON 是什么以及为什么格式很重要

JSON 是 JavaScript 对象表示法的缩写，是计算机在网络上交换结构化数据的最常见方式。 API、配置文件和许多应用程序都使用 JSON，因为它易于阅读且易于机器解析。有效的 JSON 文档是由大括号中的对象、方括号中的数组、双引号中的字符串、数字以及值 true、false 和 null 构建的。格式化不会改变数据的含义，但会改变人们阅读的容易程度。缩小后的 JSON 删除了所有空格，变得更小，通过网络发送的速度更快，这就是 API 使用它的原因，但它几乎无法读取或调试。美化的 JSON 具有两个空格缩进和每行一个值，虽然更大，但可以让您在几秒钟内发现缺少的逗号或错误的括号。

最常见的 JSON 错误

  • 缺少或多余的逗号：对象或数组中除最后一项之外的每一项都需要逗号，并且严格的 JSON 中不允许最后一项后面有尾随逗号。
  • 单引号而不是双引号：JSON 字符串必须使用双引号，尽管 JavaScript 代码通常允许单引号。
  • 不带引号的键：对象键必须是带引号的字符串，因此 {name: "Ana"} 无效，必须是 {"name": "Ana"}。
  • 注释：JSON 不允许注释，因此以 // 开头的行将中断解析，即使它们看起来无害。
  • 尾随文本或多文档：连续粘贴两个 JSON 对象是无效的；将它们包装在一个数组中或一次修复一个。

格式化与缩小：何时使用两者

当您阅读、调试或学习 JSON 时，请使用 Format，因为缩进一目了然地揭示了结构并使嵌套变得明显。当您需要将 JSON 粘贴到 URL、紧凑的配置字段、测试请求或大小重要而可读性不重要的消息中时，请使用 Minify。仅当您只需要是或否答案时（例如在保存配置文件之前）使用“验证”，因为它会检查 JSON 而不替换原始文本。在所有这三种情况下，该工具首先解析 JSON，因此保证缩小或格式化的结果是有效的；如果解析失败，您会得到一个错误，而不是一个无提示的损坏输出，这正是您在发送代码之前想要的。

隐私和限制

该格式化程序完全在您的浏览器中运行。您的 JSON 永远不会被上传、记录或共享，这一点很重要，因为 JSON 通常包含 API 密钥、个人数据或内部配置。切勿将机密粘贴到您不信任的任何在线格式化程序中，并轮换您意外泄露的任何密钥。该工具可以轻松处理典型的 API 响应和配置文件，但非常大的文档（数十兆字节）在浏览器选项卡中可能会很慢，因为解析和重新字符串化它们会占用内存。它还遵循严格的 JSON 规则，因此它将拒绝 JavaScript 风格的额外内容，例如尾随逗号、单引号和注释，即使某些工具宽松地接受它们。

常见问题 (FAQ)

格式化和缩小有什么区别？
格式添加了缩进和换行符，因此 JSON 易于人类阅读。 Minify 删除所有不必要的空格和换行符，因此 JSON 尽可能小以便发送或存储。
为什么我的 JSON 会失败并出现尾随逗号错误？
严格的 JSON 不允许在对象或数组中的最后一项后使用逗号。删除最后一个逗号，JSON 将被解析。
我可以在 JSON 中使用单引号吗？
不可以。JSON 字符串和键必须使用双引号。单引号在 JavaScript 代码中有效，但它们不是有效的 JSON，该工具将正确拒绝它们。
我的 JSON 数据是否存储或发送到任何地方？
不会。格式化和验证完全在您的浏览器中运行，因此您的数据永远不会离开您的设备。
格式化会改变我的数据吗？
不会。格式化和缩小只会改变间距和换行符。只要 JSON 一开始就有效，值、键和结构就保持完全相同。
