如何使用 Base64 编码器

  1. 输入您的文字键入或粘贴纯文本进行编码，或粘贴 Base64 字符串进行解码。
  2. 选择编码或解码按“编码”将文本转换为 Base64，或按“解码”将 Base64 重新转换为可读文本。
  3. 检查一下错误是否有无效的 Base64 显示解释问题的友好错误，而不是空白或乱码结果。
  4. 复制结果使用复制输出将结果放入电子邮件、配置文件、API 请求或消息中。

Base64 是什么以及它为何存在

Base64 是一种表示任何字节（包括文本、图像和文件）的方法，仅使用 64 个安全字符：大写字母和小写字母、数字、加号和斜杠，并在末尾使用等号作为填充。计算机通常需要通过仅安全处理纯文本的系统发送二进制数据，例如电子邮件标头、网址、JSON 字段和配置文件。这些地方的原始字节可能会被损坏、误读或拒绝，因此 Base64 将它们转换为在整个旅程中保持不变的文本。权衡是大小：Base64 输出大约比原始数据大三分之一，因为三个字节变成四个字符。这对于令牌、小图像和短字符串来说是可以接受的，但对于非常大的文件来说是浪费的，这就是 Base64 不用于流视频或大型下载的原因。

为什么 Unicode 需要特别关注

简单 Base64 工具的一个常见错误是它们会在非英语文本上崩溃。旧的浏览器功能 btoa 和 atob 仅处理拉丁字符，因此像咖啡馆这样的词、乌尔都语或希腊语的名称或表情符号可能会产生错误或垃圾。该工具首先使用 TextEncoder 将文本转换为 UTF-8 字节，对这些字节进行编码，然后在解码时使用 TextDecoder 反转该过程，从而完全避免了该错误。这意味着“Hola”、“Kαλημέρα”、“Müržamba” 和一个微笑的表情符号都可以正确地往返：对它们进行编码，对结果进行解码，然后您就可以准确地得到原始文本。如果另一个工具为您提供了重音或非拉丁文本的损坏字符，那么它几乎肯定使用了裸 btoa 和 atob，而不进行 UTF-8 处理，您应该切换到像这样的 Unicode 安全工具。

常见用途和安全警告

  • 数据 URL：小图像和图标通常以 Base64 形式直接嵌入网页中，因此页面不需要单独的图像文件。
  • API 令牌和基本身份验证：用户名、密码和令牌有时在标头中进行 Base64 编码，但这不是加密，必须始终通过 HTTPS 传输。
  • 电子邮件附件：电子邮件系统以 Base64 编码附件，以便二进制文件可以通过纯文本邮件服务器传输。
  • 配置和测试：开发人员对短字符串进行编码以测试 API，在 JSON 中存储小 blob，并比较值而无需担心特殊字符。

隐私和限制

Base64是编码，不是加密。任何看到 Base64 字符串的人都可以在几秒钟内对其进行解码，因此切勿使用它来隐藏密码、密钥或私人信息，也切勿将其视为安全的。该工具完全在您的浏览器中运行，因此您的文本永远不会上传或存储，但输出本身仍然可供您与之共享的任何人读取。该工具接受标准 Base64 和使用减号和下划线而不是加号和斜杠的 URL 安全变体，并且它可以容忍换行和缺失填充，这使得它可以容忍从电子邮件复制的字符串。非常大的输入在浏览器选项卡中可能会很慢，因此对于多兆字节的文件，请改用桌面工具。

常见问题 (FAQ)

是Base64加密吗？
不。Base64 只是编码，是一种可逆的格式变化。任何人都可以立即解码 Base64 字符串，因此绝不能用它来隐藏密码或秘密。
为什么我的重音文本在某些 Base64 工具中会中断？
这些工具使用裸 btoa 和 atob，它们仅处理拉丁字符。该工具首先将文本转换为 UTF-8 字节，因此重音字母、希腊语、乌尔都语和表情符号都可以正常工作。
为什么 Base64 输出比我的文本长？
Base64 将每 3 个字节转换为 4 个字符，因此输出大约大 33%。这是使二进制数据对于纯文本系统安全的正常代价。
末尾的等号是做什么用的？
等号是填充。当输入长度不是三的倍数时，它们将最终组填充为四个字符，因此解码器确切地知道数据结束的位置。
我的文本会发送到服务器吗？
不会。编码和解码完全在您的浏览器中运行，您输入的任何内容都不会离开您的设备。
