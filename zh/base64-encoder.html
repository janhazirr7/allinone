怎样使用 Base64 编码器

  1. 输入你的文本输入或粘贴要编码的纯文本，或粘贴要解码的 Base64 字符串。
  2. 选择编码或解码点击“编码”把文本变成 Base64，或点击“解码”把 Base64 变回可读文本。
  3. 如果有错误，检查错误信息无效的 Base64 会显示一条友好的错误信息来解释问题，而不是空白或乱码结果。
  4. 复制结果使用“复制输出”把结果带入电子邮件、配置文件、API 请求或消息。

什么是 Base64 以及它为什么存在

Base64 是一种用仅 64 个安全字符表示任何字节（包括文本、图像和文件）的方法：大小写字母、数字、加号和斜杠，末尾用等号作为填充。计算机常常需要通过只安全处理纯文本的系统发送二进制数据，例如电子邮件头、网址、JSON 字段和配置文件。这些地方的原始字节可能被损坏、误读或拒绝，所以 Base64 把它们翻译成在传输中保持不变的文本。代价是大小：Base64 输出比原始数据大约三分之一，因为三个字节变成四个字符。这对令牌、小图像和短字符串来说可以接受，但对非常大的文件来说很浪费，这就是 Base64 不用于流媒体视频或大文件下载的原因。

为什么 Unicode 需要特别处理

简单 Base64 工具中的一个常见错误是它们会在非英语文本上损坏。旧的浏览器函数 btoa 和 atob 只处理拉丁字符，所以像 café 这样的词、乌尔都语或希腊语名字或表情符号都可能产生错误或乱码。本工具通过先用 TextEncoder 把你的文本转换为 UTF-8 字节、对这些字节编码，并在解码时用 TextDecoder 反转这个过程，彻底避免了这个错误。这意味着 Hola、Καλημέρα、مرحبا 和一个微笑表情都能正确地往返：编码它们，再解码结果，你会得到完全相同的原文。如果另一个工具对带重音或非拉丁文本给出损坏的字符，它几乎肯定是使用了没有 UTF-8 处理的裸 btoa 和 atob，你应该换用像本工具这样的 Unicode 安全工具。

常见用途和安全警告

  • 数据 URL：小图像和图标常常直接以 Base64 嵌入网页，这样页面就不需要单独的图像文件。
  • API 令牌和基本认证：用户名、密码和令牌有时会在请求头中进行 Base64 编码，但这不是加密，必须始终通过 HTTPS 传输。
  • 电子邮件附件：电子邮件系统用 Base64 对附件编码，这样二进制文件就能通过纯文本邮件服务器传输。
  • 配置和测试：开发者对短字符串编码来测试 API、在 JSON 中存储小数据块，并在不担心特殊字符的情况下比较值。

隐私和限制

Base64 是编码，不是加密。任何看到 Base64 字符串的人都可以在几秒钟内解码，所以永远不要用它来隐藏密码、密钥或私人信息，也永远不要把它当作安全的。本工具完全在你的浏览器中运行，所以你的文本绝不会被上传或存储，但输出本身仍然可以被你分享给的任何人阅读。工具接受标准 Base64 和使用减号和下划线代替加号和斜杠的 URL 安全变体，并容忍换行和缺失的填充，这让它对从电子邮件中复制的字符串很宽容。非常大的输入在浏览器标签页中可能会变慢，所以对于几兆字节的文件，请改用桌面工具。

常见问题

Base64 是加密吗？
不会。Base64 只是编码，一种可逆的格式转换。任何人都可以立即解码 Base64 字符串，所以绝不能用它来隐藏密码或机密。
为什么我的带重音文本在某些 Base64 工具中会损坏？
那些工具使用裸 btoa 和 atob，只处理拉丁字符。本工具先把文本转换为 UTF-8 字节，所以带重音的字母、希腊语、乌尔都语和表情符号都能正常工作。
为什么 Base64 输出比我的文本长？
Base64 把每 3 个字节变成 4 个字符，所以输出大约大 33%。这是让二进制数据对纯文本系统安全的正常代价。
末尾的等号是做什么用的？
等号是填充。当输入长度不是三的倍数时，它们把最后一组补足为四个字符，这样解码器就能确切知道数据在哪里结束。
我的文本会被发送到服务器吗？
不会。编码和解码完全在你的浏览器中运行，你输入的任何东西都不会离开你的设备。
