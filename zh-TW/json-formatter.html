如何使用 JSON 格式化程式

  1. 貼上您的 JSON從 API、設定檔或教學課程複製 JSON，並將其貼到大框框中。
  2. 選擇一個動作按“格式”使其具有縮排可讀性，按“縮小”將其縮小為一行，或按“僅驗證”以檢查它而不更改它。
  3. 如果有錯誤請閱讀如果 JSON 無效，工具會以簡單的文字顯示解析器的確切錯誤，以便您知道要修復什麼。
  4. 複製結果使用複製輸出將格式化或縮小的 JSON 傳回您的程式碼、設定或 API 工具。

JSON 是什麼以及為什麼格式很重要

JSON 是 JavaScript 物件表示法的縮寫，是電腦在網路上交換結構化資料最常見的方式。 API、設定檔和許多應用程式都使用 JSON，因為它易於閱讀且易於機器解析。有效的 JSON 檔案是由大括號中的物件、方括號中的陣列、雙引號中的字串、數字以及值 true、false 和 null 建構的。格式化不會改變資料的含義，但會改變人們閱讀的容易程度。縮小後的 JSON 刪除了所有空格，變得更小，透過網路傳送的速度更快，這就是 API 使用它的原因，但它幾乎無法讀取或除錯。美化的 JSON 具有兩個空格縮排和每行一個值，雖然更大，但可以讓您在幾秒鐘內發現缺少的逗號或錯誤的括號。

最常見的 JSON 錯誤

  • 缺少或多餘的逗號：物件或陣列中除最後一項之外的每一項都需要逗號，並且嚴格的 JSON 中不允許最後一項後面有尾隨逗號。
  • 單引號而不是雙引號：JSON 字串必須使用雙引號，儘管 JavaScript 程式碼通常允許單引號。
  • 不含引號的鍵：物件鍵必須是引號的字串，因此 {name: "Ana"} 無效，必須是 {"name": "Ana"}。
  • 註釋：JSON 不允許註釋，因此以 // 開頭的行將中斷解析，即使它們看起來無害。
  • 尾隨文字或多檔案：連續貼上兩個 JSON 物件是無效的；將它們包裝在一個陣列中或一次修復一個。

格式化與縮小：何時使用兩者

當您閱讀、除錯或學習 JSON 時，請使用 Format，因為縮排一目瞭然地揭示了結構並使巢狀變得明顯。當您需要將 JSON 貼到 URL、緊湊的設定欄位、測試請求或大小重要且可讀性不重要的訊息中時，請使用 Minify。只有當您只需要是或否答案時（例如在儲存設定檔之前）使用“驗證”，因為它會檢查 JSON 而不替換原始文字。在所有這三種情況下，工具首先解析 JSON，因此保證縮小或格式化的結果是有效的；如果解析失敗，您會得到一個錯誤，而不是一個無提示的損壞輸出，這正是您在傳送程式碼之前想要的。

隱私和限制

該格式化程式完全在您的瀏覽器中執行。您的 JSON 永遠不會被上傳、記錄或分享，這一點很重要，因為 JSON 通常包含 API 金鑰、個人資料或內部配置。切勿將機密貼到您不信任的任何線上格式化程式中，並輪換您意外洩漏的任何金鑰。該工具可以輕鬆處理典型的 API 回應和設定檔案，但非常大的檔案（數十兆位元組）在瀏覽器標籤中可能會很慢，因為解析和重新字串化它們會佔用記憶體。它還遵循嚴格的 JSON 規則，因此它將拒絕 JavaScript 風格的額外內容，例如尾隨逗號、單引號和註釋，即使某些工具寬鬆地接受它們。

常見問題 (FAQ)

格式化和縮小有什麼區別？
格式新增了縮排和換行符，因此 JSON 易於人類閱讀。 Minify 刪除所有不必要的空格和換行符，因此 JSON 盡可能小以便傳送或儲存。
為什麼我的 JSON 會失敗並出現尾隨逗號錯誤？
嚴格的 JSON 不允許在物件或陣列中的最後一項後使用逗號。刪除最後一個逗號，JSON 將會被解析。
我可以在 JSON 中使用單引號嗎？
不可以。 JSON 字串和鍵必須使用雙引號。單引號可以在 JavaScript 程式碼中使用，但它們不是有效的 JSON，該工具將正確拒絕它們。
我的 JSON 資料是否儲存或傳送到任何地方？
不會。格式化和驗證完全在您的瀏覽器中執行，因此您的資料永遠不會離開您的裝置。
格式化會改變我的資料嗎？
不會。格式化和縮小隻會改變間距和換行符號。只要 JSON 一開始就有效，值、鍵和結構就保持完全相同。
