如何使用 JSON 格式化工具

  1. 貼上你的 JSON從 API、設定檔或教學中複製 JSON，貼到大的輸入框中。
  2. 選擇操作按下「格式化」以縮排讓它易讀，按下「壓縮」縮為一行，或按下「僅驗證」在不更動內容的情況下檢查它。
  3. 若有錯誤，請閱讀錯誤訊息若 JSON 無效，本工具會以淺顯的文字顯示解析器的確切錯誤，讓你知道該修正什麼。
  4. 複製結果使用「複製輸出」，將格式化或壓縮後的 JSON 帶回你的程式碼、設定檔或 API 工具。

什麼是 JSON，為何排版很重要

JSON 是 JavaScript Object Notation（JavaScript 物件表示法）的縮寫，是電腦在網路上交換結構化資料最常見的方式。API、設定檔與許多應用程式都使用 JSON，因為它易於閱讀，也容易讓機器解析。一份有效的 JSON 文件由大括號的物件、方括號的陣列、雙引號的字串、數字，以及 true、false 與 null 這些值組成。排版不會改變資料的意義，但會改變人類閱讀的難易程度。壓縮後的 JSON 移除了所有空格，體積較小、透過網路傳送較快，這也是 API 使用它的原因，但幾乎無法閱讀或除錯。美化後的 JSON 以兩個空格縮排、每行一個值，體積較大，卻能讓你在幾秒內發現缺少的逗號或錯誤的括號。

最常見的 JSON 錯誤

  • 缺少或多餘的逗號：物件或陣列中除最後一項外的每一項都需要逗號，而在嚴格的 JSON 中，最後一項後面不允許有尾隨逗號。
  • 使用單引號而非雙引號：JSON 字串必須使用雙引號，即使 JavaScript 程式碼常允許單引號。
  • 未加引號的鍵：物件的鍵必須是加引號的字串，因此 {name: "Ana"} 是無效的，必須寫成 {"name": "Ana"}。
  • 註解：JSON 不允許註解，因此以 // 開頭的行即使看似無害，也會導致解析失敗。
  • 尾隨文字或多份文件：連續貼上兩個 JSON 物件是無效的；請將它們包在陣列中，或一次修正一份。

格式化與壓縮：何時使用哪一種

閱讀、除錯或學習 JSON 時請使用「格式化」，因為縮排能一眼揭示結構，讓巢狀關係一目了然。需要將 JSON 貼入網址、精簡的設定欄位、測試請求或訊息，且體積重要、可讀性不重要時，請使用「壓縮」。只需要是或否的答案時，例如儲存設定檔之前，請使用「僅驗證」，因為它會在不取代原始文字的情況下檢查 JSON。以上三種情況，本工具都會先解析 JSON，因此壓縮或格式化後的結果保證有效；若解析失敗，你會得到錯誤訊息，而非悄悄損毀的輸出，這正是發佈程式碼前想要的保障。

隱私與限制

本格式化工具完全在你的瀏覽器內執行。你的 JSON 絕不會被上傳、記錄或分享，這很重要，因為 JSON 常包含 API 金鑰、個人資料或內部設定。絕不要將機密貼入任何你不信任的線上格式化工具，並請更換任何不慎外洩的金鑰。本工具能輕鬆處理典型的 API 回應與設定檔，但極大的文件（數十 MB）可能在瀏覽器分頁中變慢，因為解析與重新轉為字串需要記憶體。它也遵循嚴格的 JSON 規則，因此會拒絕 JavaScript 風格的額外寫法，例如尾隨逗號、單引號與註解，即使有些工具會寬鬆接受它們。

常見問題（FAQs）

格式化與壓縮有什麼差別？
格式化會加入縮排與換行，讓人類容易閱讀 JSON。壓縮會移除所有不必要的空格與換行，讓 JSON 盡可能小，便於傳送或儲存。
為什麼我的 JSON 會因尾隨逗號而失敗？
嚴格的 JSON 不允許在物件或陣列的最後一項後面加上逗號。移除最後那個逗號，JSON 就能解析。
我可以在 JSON 中使用單引號嗎？
不行。JSON 字串與鍵必須使用雙引號。單引號在 JavaScript 程式碼中可用，但在 JSON 中無效，本工具會正確拒絕它們。
我的 JSON 資料會被儲存或傳送到任何地方嗎？
不會。格式化與驗證完全在你的瀏覽器內執行，因此你的資料絕不會離開你的裝置。
格式化會改變我的資料嗎？
不會。格式化與壓縮只改變空格與換行。只要原本的 JSON 有效，數值、鍵與結構都會保持完全相同。
