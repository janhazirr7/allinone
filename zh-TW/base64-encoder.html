如何使用 Base64 編碼器

  1. 輸入您的文字鍵入或貼上純文字進行編碼，或貼上 Base64 字串進行解碼。
  2. 選擇編碼或解碼按下「編碼」將文字轉換為 Base64，或按「解碼」將 Base64 重新轉換為可讀文字。
  3. 檢查一下錯誤是否有無效的 Base64 顯示解釋問題的友善錯誤，而不是空白或亂碼結果。
  4. 複製結果使用複製輸出將結果放入電子郵件、設定檔、API 請求或訊息中。

Base64 是什麼以及它為何存在

Base64 是一種表示任何位元組（包括文字、影象和檔案）的方法，僅使用 64 個安全字元：大寫字母和小寫字母、數字、加號和斜槓，並在末尾使用等號作為填充。電腦通常需要透過僅安全處理純文字的系統傳送二進位資料，例如電子郵件標頭、網址、JSON 欄位和設定檔。這些地方的原始位元組可能會被損壞、誤讀或拒絕，因此 Base64 將它們轉換為在整個旅程中保持不變的文字。權衡是大小：Base64 輸出大約比原始資料大三分之一，因為三個位元組變成四個字元。這對於令牌、小影象和短字串來說是可以接受的，但對於非常大的檔案來說是浪費的，這就是 Base64 不用於串流影片或大型下載的原因。

為什麼 Unicode 需要特別關注

簡單 Base64 工具的一個常見錯誤是它們會在非英語文字上崩潰。舊的瀏覽器功能 btoa 和 atob 僅處理拉丁字元，因此像咖啡館這樣的詞、烏爾都語或希臘語的名稱或表情符號可能會產生錯誤或垃圾。該工具首先使用 TextEncoder 將文字轉換為 UTF-8 位元組，對這些位元組進行編碼，然後在解碼時使用 TextDecoder 反轉該過程，從而完全避免了該錯誤。這意味著“Hola”、“Kαλημέρα”、“Müržamba” 和一個微笑的表情符號都可以正確地往返：對它們進行編碼，對結果進行解碼，然後您就可以準確地得到原始文字。如果另一個工具為您提供了重音或非拉丁文字的損壞字元，那麼它幾乎肯定使用了裸 btoa 和 atob，而不進行 UTF-8 處理，您應該切換到像這樣的 Unicode 安全工具。

常見用途和安全警告

  • 資料 URL：小影象和圖示通常以 Base64 形式直接嵌入網頁中，因此頁面不需要單獨的影象檔案。
  • API 令牌和基本驗證：使用者名稱、密碼和令牌有時會在標頭中進行 Base64 編碼，但這不是加密，必須始終透過 HTTPS 傳輸。
  • 電子郵件附件：電子郵件系統以 Base64 編碼附件，以便二進位檔案可以透過純文字郵件伺服器傳輸。
  • 配置和測試：開發人員對短字串進行編碼以測試 API，在 JSON 中儲存小 blob，並比較值而無需擔心特殊字元。

隱私和限制

Base64是編碼，不是加密。任何看到 Base64 字串的人都可以在幾秒鐘內對其進行解碼，因此切勿使用它來隱藏密碼、金鑰或私人訊息，也切勿將其視為安全的。該工具完全在您的瀏覽器中執行，因此您的文字永遠不會上傳或儲存，但輸出本身仍然可供您與之共享的任何人讀取。該工具接受標準 Base64 和使用減號和下劃線而不是加號和斜槓的 URL 安全變體，並且它可以容忍換行和缺失填充，這使得它可以容忍從電子郵件複製的字串。非常大的輸入在瀏覽器標籤中可能會很慢，因此對於多兆位元組的檔案，請改用桌面工具。

常見問題 (FAQ)

是Base64加密嗎？
不。 Base64 只是編碼，是一種可逆的格式變化。任何人都可以立即解碼 Base64 字串，因此絕不能用它來隱藏密碼或秘密。
為什麼我的重音文字在某些 Base64 工具中會中斷？
這些工具使用裸 btoa 和 atob，它們只處理拉丁字元。該工具首先將文字轉換為 UTF-8 位元組，因此重音字母、希臘語、烏爾都語和表情符號都可以正常運作。
為什麼 Base64 輸出比我的文字長？
Base64 將每 3 個位元組轉換為 4 個字元，因此輸出大約大 33%。這是使二進位資料對於純文字系統安全的正常代價。
末尾的等號是做什麼用的？
等號是填充。當輸入長度不是三的倍數時，它們將最終組填充為四個字元，因此解碼器確切地知道資料結束的位置。
我的文字會傳送到伺服器嗎？
不會。編碼和解碼完全在您的瀏覽器中執行，您輸入的任何內容都不會離開您的裝置。
