Paano Gamitin ang JSON Formatter

  1. I-paste ang iyong JSONKopyahin ang JSON mula sa isang API, isang config file o isang tutorial at i-paste ito sa malaking box.
  2. Pumili ng isang aksyonPindutin ang I-format upang gawin itong madaling basahin gamit ang indentation, Paliitin upang paliitin ito sa isang linya, o I-validate Lamang upang suriin ito nang hindi ito binabago.
  3. Basahin ang error kung mayroonKung ang JSON ay di-balido, ipinapakita ng tool ang eksaktong error mula sa parser sa payak na mga salita, upang malaman mo kung ano ang aayusin.
  4. Kopyahin ang resultaGamitin ang Kopyahin ang Output upang dalhin ang naka-format o naka-minify na JSON pabalik sa iyong code, config o API tool.

Ano ang JSON at Bakit Mahalaga ang Pag-format

Ang JSON, maikli para sa JavaScript Object Notation, ang pinakakaraniwang paraan ng pagpapalitan ng mga computer ng structured na datos sa web. Ang mga API, configuration file at maraming app ay nagsasalita lahat ng JSON dahil simple itong basahin at madali para sa mga makina na i-parse. Ang isang balidong dokumento ng JSON ay binubuo ng mga object sa curly braces, mga array sa square brackets, mga string sa double quotes, mga numero, at ang mga value na true, false at null. Ang pag-format ay hindi nagbabago sa ibig sabihin ng datos, ngunit binabago nito kung gaano ito kadali para sa isang tao na basahin. Ang minified na JSON, na inalis ang lahat ng espasyo, ay mas maliit at mas mabilis ipadala sa isang network, kaya ginagamit ito ng mga API, ngunit halos imposible itong basahin o i-debug. Ang beautified na JSON, na may two-space indentation at isang value kada linya, ay mas malaki ngunit hinahayaan kang makita ang isang nawawalang kuwit o maling bracket sa loob ng ilang segundo.

Ang Pinakakaraniwang mga Error sa JSON

  • Nawawala o sobrang mga kuwit: ang bawat item sa isang object o array maliban sa huli ay nangangailangan ng isang kuwit, at ang isang trailing comma pagkatapos ng huling item ay hindi pinapayagan sa mahigpit na JSON.
  • Mga single quote sa halip na double quotes: ang mga string ng JSON ay dapat gumamit ng double quotes, kahit na ang JavaScript code ay madalas na nagpapahintulot ng single quotes.
  • Mga key na walang panipi: ang mga object key ay dapat na mga string na may panipi, kaya ang {name: "Ana"} ay di-balido at dapat na {"name": "Ana"}.
  • Mga komento: hindi pinapayagan ng JSON ang mga komento, kaya ang mga linyang nagsisimula sa // ay makakasira sa pag-parse kahit na mukha silang hindi nakakapinsala.
  • Trailing text o maraming dokumento: ang pag-paste ng dalawang JSON object nang sunod-sunod ay di-balido; balutin ang mga ito sa isang array o ayusin ang mga ito nang paisa-isa.

Pag-format Kumpara sa Pag-minify: Kailan Gagamitin ang Bawat Isa

Gamitin ang I-format kapag nagbabasa, nagde-debug o natututo mula sa JSON, dahil ang indentation ay nagpapakita ng istraktura sa isang tingin at ginagawang halata ang nesting. Gamitin ang Paliitin kapag kailangan mong i-paste ang JSON sa isang URL, isang compact na config field, isang test request o isang mensahe kung saan mahalaga ang laki at hindi ang readability. Gamitin ang I-validate Lamang kapag kailangan mo lamang ng isang oo-o-hindi na sagot, halimbawa bago mag-save ng isang config file, dahil sinusuri nito ang JSON nang hindi pinapalitan ang iyong orihinal na text. Sa lahat ng tatlong kaso, una munang pino-parse ng tool ang JSON, kaya ang isang minified o naka-format na resulta ay garantisadong balido; kung nabigo ang pag-parse, makakakuha ka ng isang error sa halip na isang tahimik na sirang output, na eksaktong gusto mo bago mag-ship ng code.

Privacy at mga Limitasyon

Ang formatter na ito ay ganap na tumatakbo sa iyong browser. Ang iyong JSON ay hindi kailanman ina-upload, naka-log o ibinabahagi, na mahalaga dahil ang JSON ay madalas na naglalaman ng mga API key, personal na datos o panloob na configuration. Huwag kailanman mag-paste ng mga lihim sa anumang online formatter na hindi mo pinagkakatiwalaan, at i-rotate ang anumang key na aksidente mong nailantad. Madaling hinahawakan ng tool ang mga karaniwang tugon ng API at config file, ngunit ang napakalalaking dokumento, na sampu-sampung megabytes, ay maaaring bumagal sa isang browser tab dahil ang pag-parse at muling pag-stringify sa mga ito ay kumukuha ng memorya. Sinusundan din nito ang mahigpit na mga panuntunan sa JSON, kaya tatanggihan nito ang mga JavaScript-style na dagdag tulad ng trailing commas, single quotes at komento, kahit na ang ilang tool ay maluwag na tinatanggap ang mga ito.

Mga Madalas Itanong (FAQs)

Ano ang pagkakaiba ng I-format at Paliitin?
Nagdaragdag ang I-format ng indentation at mga line break upang madaling basahin ng mga tao ang JSON. Inaalis ng Paliitin ang lahat ng hindi kailangang espasyo at line break upang ang JSON ay maging kasingliit hangga't maaari para sa pagpapadala o pag-iimbak.
Bakit nabibigo ang aking JSON na may trailing comma error?
Hindi pinapayagan ng mahigpit na JSON ang isang kuwit pagkatapos ng huling item sa isang object o array. Alisin ang huling kuwit na iyan at ang JSON ay magpa-parse.
Maaari ba akong gumamit ng single quotes sa JSON?
Hindi. Ang mga string at key ng JSON ay dapat gumamit ng double quotes. Gumagana ang mga single quote sa JavaScript code, ngunit hindi ito balidong JSON at tatanggihan ito ng tool na ito nang tama.
Naka-save ba o ipinapadala kahit saan ang aking datos sa JSON?
Hindi. Ang pag-format at pag-validate ay ganap na tumatakbo sa iyong browser, kaya ang iyong datos ay hindi kailanman umaalis sa iyong device.
Binabago ba ng pag-format ang aking datos?
Hindi. Ang pag-format at pag-minify ay nagbabago lamang ng spacing at mga line break. Ang mga value, key at istraktura ay nananatiling eksaktong pareho, hangga't ang JSON ay balido sa simula pa lang.
