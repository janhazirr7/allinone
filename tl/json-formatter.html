Paano Gamitin ang JSON Formatter

  1. I-paste ang iyong JSONKopyahin ang JSON mula sa isang API, isang config file o isang tutorial at i-paste ito sa malaking kahon.
  2. Pumili ng aksyonPindutin ang Format para gawin itong nababasa na may indentation, Minify para paliitin ito sa isang linya, o Validate Only para suriin ito nang hindi binabago.
  3. Basahin ang error kung mayroon manKung hindi wasto ang JSON, ipinapakita ng tool ang eksaktong error mula sa parser sa mga simpleng salita, para malaman mo kung ano ang aayusin.
  4. Kopyahin ang resultaGamitin ang Copy Output para ibalik ang naka-format o minified na JSON sa iyong code, config o API tool.

Ano ang JSON at Bakit Mahalaga ang Pag-format

Ang JSON, maikli para sa JavaScript Object Notation, ay ang pinakakaraniwang paraan ng pagpapalitan ng mga computer ng structured na data sa web. Ang mga API, configuration file at maraming app ay nagsasalita ng JSON dahil simple itong basahin at madaling i-parse ng mga machine. Ang isang wastong dokumento ng JSON ay binuo mula sa mga bagay sa mga kulot na brace, mga array sa mga square bracket, mga string sa double quote, mga numero, at ang mga value na true, false at null. Hindi binabago ng pag-format ang ibig sabihin ng data, ngunit binabago nito kung gaano kadaling basahin ng isang tao. Ang pinaliit na JSON, na inalis ang lahat ng mga puwang, ay mas maliit at mas mabilis na ipadala sa isang network, kaya naman ginagamit ito ng mga API, ngunit halos imposibleng basahin o i-debug. Ang pinaganda na JSON, na may two-space indentation at isang value sa bawat linya, ay mas malaki ngunit hinahayaan kang makakita ng nawawalang kuwit o maling bracket sa loob ng ilang segundo.

Ang Pinakakaraniwang Mga Error sa JSON

  • Nawawala o dagdag na kuwit: bawat item sa isang bagay o array maliban sa huli ay nangangailangan ng kuwit, at isang trailing comma pagkatapos ng huling item ay hindi pinapayagan sa mahigpit na JSON.
  • Mga solong quote sa halip na double quote: Ang mga string ng JSON ay dapat gumamit ng mga double quote, kahit na madalas na pinapayagan ng JavaScript code ang mga solong quote.
  • Mga hindi naka-quote na key: ang mga object key ay dapat na may panipi na mga string, kaya ang {name: "Ana"} ay hindi wasto at dapat ay {"name": "Ana"}.
  • Mga Komento: Hindi pinapayagan ng JSON ang mga komento, kaya ang mga linyang nagsisimula sa // ay masisira ang pag-parse kahit na mukhang hindi nakakapinsala ang mga ito.
  • Trailing text o maraming dokumento: hindi wasto ang pag-paste ng dalawang JSON object nang sunud-sunod; balutin ang mga ito sa isang array o ayusin ang mga ito nang paisa-isa.

Pag-format Versus Minifying: Kailan Gagamitin ang Bawat isa

Gamitin ang Format kapag nagbabasa ka, nagde-debug o natututo mula sa JSON, dahil ang indentation ay nagpapakita ng istraktura sa isang sulyap at ginagawang halata ang nesting. Gamitin ang Minify kapag kailangan mong i-paste ang JSON sa isang URL, isang compact na config field, isang kahilingan sa pagsubok o isang mensahe kung saan mahalaga ang laki at ang pagiging madaling mabasa ay hindi. Gamitin ang Validate Only kapag kailangan mo lang ng yes-or-no na sagot, halimbawa bago mag-save ng config file, dahil sinusuri nito ang JSON nang hindi pinapalitan ang iyong orihinal na text. Sa lahat ng tatlong kaso, ang tool ay unang nag-parse ng JSON, kaya ang isang minified o na-format na resulta ay ginagarantiyahan na wasto; kung nabigo ang pag-parse, magkakaroon ka ng error sa halip na isang tahimik na sirang output, na kung ano mismo ang gusto mo bago ang shipping code.

Privacy at Limitasyon

Ang formatter na ito ay ganap na tumatakbo sa iyong browser. Ang iyong JSON ay hindi kailanman na-upload, naka-log o nakabahagi, na mahalaga dahil ang JSON ay madalas na naglalaman ng mga API key, personal na data o panloob na configuration. Huwag kailanman mag-paste ng mga lihim sa anumang online na formatter na hindi mo pinagkakatiwalaan, at i-rotate ang anumang key na hindi mo sinasadyang ilantad. Ang tool ay madaling humahawak ng mga tipikal na tugon ng API at mga config file, ngunit ang napakalaking mga dokumento, sampu-sampung megabytes, ay maaaring mabagal sa isang tab ng browser dahil ang pag-parse at muling pag-string ng mga ito ay nangangailangan ng memorya. Sinusunod din nito ang mga mahigpit na panuntunan ng JSON, kaya tatanggihan nito ang mga ekstrang istilo ng JavaScript tulad ng mga trailing na kuwit, iisang quote at komento, kahit na maluwag na tinatanggap ng ilang tool ang mga ito.

Mga Madalas Itanong (FAQs)

Ano ang pagkakaiba sa pagitan ng Format at Minify?
Ang format ay nagdaragdag ng indentation at line break para madaling mabasa ng mga tao ang JSON. Tinatanggal ng Minify ang lahat ng hindi kinakailangang espasyo at mga line break upang ang JSON ay kasing liit hangga't maaari para sa pagpapadala o pag-iimbak.
Bakit nabigo ang aking JSON na may trailing comma error?
Hindi pinapayagan ng mahigpit na JSON ang isang kuwit pagkatapos ng huling item sa isang bagay o array. Alisin ang huling kuwit at ang JSON ay mag-parse.
Maaari ba akong gumamit ng mga solong panipi sa JSON?
Hindi. Ang mga string at key ng JSON ay dapat gumamit ng double quotes. Gumagana ang mga solong quote sa JavaScript code, ngunit hindi ito wastong JSON at tama na tatanggihan ng tool na ito ang mga ito.
Ang aking JSON data ba ay nakaimbak o ipinadala kahit saan?
Hindi. Ang pag-format at pagpapatunay ay ganap na tumatakbo sa iyong browser, kaya ang iyong data ay hindi umaalis sa iyong device.
Binabago ba ng pag-format ang aking data?
Hindi. Ang pag-format at pagpapaliit ay nagpapalit lang ng spacing at line break. Ang mga halaga, susi at istraktura ay nananatiling eksaktong pareho, hangga't ang JSON ay wasto sa simula.
