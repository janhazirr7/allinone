  2. Piliin ang Encode o DecodePindutin ang Encode para gawing Base64 ang text, o Decode para gawing nababasang text ang Base64.

Ano ang Base64 at Bakit Ito Umiiral

Ang Base64 ay isang paraan upang kumatawan sa anumang byte, kabilang ang text, mga larawan at mga file, gamit lamang ang 64 na ligtas na mga character: malaki at maliit na mga titik, digit, plus at slash, na may katumbas na mga palatandaan bilang padding sa dulo. Kadalasan kailangan ng mga computer na magpadala ng binary data sa pamamagitan ng mga system na ligtas lamang na humahawak ng plain text, gaya ng mga email header, web address, JSON field at configuration file. Ang mga raw byte sa mga lugar na iyon ay maaaring masira, maling basahin o tanggihan, kaya't isinasalin ng Base64 ang mga ito sa teksto na hindi nagbabago sa paglalakbay. Ang trade-off ay laki: Base64 output ay humigit-kumulang isang-katlo na mas malaki kaysa sa orihinal na data, dahil ang tatlong byte ay naging apat na character. Katanggap-tanggap iyon para sa mga token, maliliit na larawan at maiikling string, ngunit maaksaya para sa napakalaking file, kaya naman hindi ginagamit ang Base64 para sa streaming na video o malalaking pag-download.

Bakit Kailangan ng Unicode ng Espesyal na Pangangalaga

Ang isang karaniwang bug sa mga simpleng tool ng Base64 ay ang pagkasira ng mga ito sa hindi Ingles na teksto. Ang lumang browser ay gumaganap ng btoa at atob na humahawak lamang ng mga Latin na character, kaya ang isang salita tulad ng café, isang pangalan sa Urdu o Greek, o isang emoji ay maaaring makagawa ng isang error o basura. Ang tool na ito ay ganap na iniiwasan ang bug na iyon sa pamamagitan ng unang pag-convert ng iyong teksto sa UTF-8 byte gamit ang TextEncoder, pag-encode ng mga byte na iyon, at pag-reverse ng proseso gamit ang TextDecoder sa pag-decode. Ibig sabihin, Hola, Καλημέρα, مرحبا at nakangiting emoji ang lahat ng round-trip nang tama: i-encode ang mga ito, i-decode ang resulta, at eksaktong maibabalik mo ang orihinal na text. Kung ang isa pang tool ay nagbibigay sa iyo ng mga sirang character para sa accented o non-Latin text, halos tiyak na gumamit ito ng bare btoa at atob nang walang UTF-8 handling, at dapat kang lumipat sa isang Unicode-safe na tool tulad ng isang ito.

Mga Karaniwang Gamit at Isang Babala sa Seguridad

  • Mga URL ng Data: ang maliliit na larawan at icon ay kadalasang direktang naka-embed sa mga web page bilang Base64, kaya hindi nangangailangan ng hiwalay na image file ang isang page.
  • Mga token ng API at pangunahing auth: ang mga username, password at token ay minsan naka-encode sa Base64 sa mga header, ngunit hindi ito pag-encrypt at dapat palaging maglakbay sa HTTPS.
  • Mga email attachment: ang mga email system ay nag-encode ng mga attachment sa Base64 upang ang mga binary file ay maaaring maglakbay sa pamamagitan ng text-only na mga mail server.
  • Config at pagsubok: ang mga developer ay nag-encode ng mga maiikling string upang subukan ang mga API, mag-imbak ng maliliit na blobs sa JSON, at maghambing ng mga value nang hindi nababahala tungkol sa mga espesyal na character.

Privacy at Limitasyon

Ang Base64 ay pag-encode, hindi pag-encrypt. Maaaring i-decode ito ng sinumang nakakakita ng Base64 string sa loob ng ilang segundo, kaya huwag na huwag itong gamitin upang itago ang isang password, isang lihim na key o pribadong impormasyon, at huwag na huwag itong ituring na secure. Ang tool na ito ay ganap na tumatakbo sa iyong browser, kaya ang iyong teksto ay hindi kailanman na-upload o nakaimbak, ngunit ang mismong output ay nababasa pa rin ng sinumang ibabahagi mo nito. Ang tool ay tumatanggap ng karaniwang Base64 at ang URL-safe na variant na gumagamit ng minus at underscore sa halip na plus at slash, at pinahihintulutan nito ang mga line break at nawawalang padding, na ginagawa itong mapagpatawad sa mga string na kinopya mula sa mga email. Maaaring mabagal ang napakalaking input sa tab ng browser, kaya para sa mga multi-megabyte na file ay gumamit na lang ng desktop tool.

Mga Madalas Itanong (FAQs)

Naka-encrypt ba ang Base64?
Hindi. Ang Base64 ay pag-encode lamang, isang nababagong pagbabago ng format. Sinuman ay maaaring agad na mag-decode ng isang Base64 string, kaya hindi ito dapat gamitin upang itago ang mga password o lihim.
Bakit nasira ang aking accented na text sa ilang tool sa Base64?
Ang mga tool na iyon ay gumagamit ng hubad na btoa at atob, na humahawak lamang ng mga Latin na character. Kino-convert muna ng tool na ito ang text sa UTF-8 bytes, kaya gumagana nang tama ang mga accent na titik, Greek, Urdu at emoji.
Bakit mas mahaba ang output ng Base64 kaysa sa aking teksto?
Ginagawa ng Base64 ang bawat 3 byte sa 4 na character, kaya humigit-kumulang 33 porsiyentong mas malaki ang output. Iyan ang normal na presyo para gawing ligtas ang binary data para sa mga text-only system.
Para saan ang equals sign sa dulo?
Katumbas ng mga palatandaan ay padding. Pinupuno nila ang panghuling pangkat sa apat na character kapag ang haba ng input ay hindi isang multiple ng tatlo, kaya alam ng decoder kung saan eksakto nagtatapos ang data.
Ipinadala ba ang aking text sa isang server?
Hindi. Ang pag-encode at pag-decode ay ganap na tumatakbo sa iyong browser at walang anumang ilalagay mo ang umalis sa iyong device.
