Paano Gamitin ang Number Base Converter

Ang mga computer, programmer, at electronics engineer ay patuloy na nagpapalipat-lipat sa pagitan ng mga base ng numero: binary para sa hardware, octal para sa mas lumang mga system at mga pahintulot ng file, decimal para sa pang-araw-araw na arithmetic, at hexadecimal bilang isang compact shorthand para sa binary. Ang converter na ito ay kumukuha ng numero sa alinman sa apat na baseng iyon at agad na ipinapakita ang lahat ng apat na value nang sabay-sabay, kaya hindi mo na kailangang mag-convert nang dalawang beses o magtaka kung legal ang isang digit sa base na iyong pinili.

  1. I-type ang iyong numeroIlagay ang value sa unang kahon, halimbawa 255, 1010, o FF. Buong di-negatibong mga numero lamang; ang mga sign at decimal point ay hindi bahagi ng mga integer base na ito.
  2. Sabihin sa converter kung saang base ito naroroonPumili ng binary, octal, decimal, o hexadecimal mula sa dropdown. Mahalaga ito: Ang ibig sabihin ng 1010 ay sampu sa binary ngunit isang libo at sampu sa decimal.
  3. Pindutin ang I-convert at basahin ang lahat ng apat na resultaAng mga binary, octal, decimal, at hexadecimal na mga halaga ay lumalabas nang magkasama, na may naka-highlight na decimal na halaga, upang maaari mong kopyahin ang alinmang bumubuo sa iyong code o takdang-aralin na kailangan.
  4. Kung may lumitaw na error, suriin ang iyong mga digitAng bawat base ay nagbibigay-daan lamang sa ilang mga numero. Binibigyang-daan lamang ng binary ang 0 at 1, kaya tinanggihan ang 102; pinapayagan ng octal ang 0 hanggang 7, kaya tinanggihan ang 89; pinapayagan ng hexadecimal ang 0 hanggang 9 at A hanggang F, kaya tinanggihan ang G.

Ano ang Number Base, at Bakit Mayroon Tayong Higit sa Isa?

Ang base ng numero, na tinatawag ding radix, ay kung gaano karaming natatanging mga digit ang ginagamit ng isang sistema ng pagbibilang bago ito dalhin sa isang bagong lugar. Ang Decimal, ang sistemang natutunan natin bilang mga bata, ay gumagamit ng sampung digit (0 hanggang 9) dahil ang mga tao ay may sampung daliri. Ang bawat posisyon ay nagkakahalaga ng sampung beses ng isa sa kanan nito: sa 255, ang mga digit ay nangangahulugang 2 daan + 5 sampu + 5 isa. Ang binary ay gumagamit lamang ng dalawang digit, 0 at 1, dahil ang computer hardware ay binuo mula sa mga switch na naka-off o naka-on. Ang bawat binary na posisyon ay doble ang halaga ng isa sa kanan nito, kaya ang 1010 ay nangangahulugang 8 + 0 + 2 + 0 = 10. Gumagamit ang Octal ng walong digit, 0 hanggang 7, at ang hexadecimal ay gumagamit ng labing-anim: 0 hanggang 9 kasama ang mga titik A hanggang F para sa mga halagang sampu hanggang labinlima.

Umiiral ang hexadecimal bilang isang kaginhawahan para sa mga tao na nagbabasa ng binary. Ang isang hexadecimal na digit ay tumutugma sa eksaktong apat na binary digit, kaya ang isang mahabang binary string tulad ng 11111111 ay maayos na nag-collapse sa FF. Iyon ang dahilan kung bakit nakikita mo ang hexadecimal sa lahat ng dako sa computing: ang mga color code sa web gaya ng #FF5733 ay talagang tatlong hexadecimal byte para sa pula, berde, at asul; ang mga address ng memorya ay ipinapakita sa hex; at ang mga network engineer ay nagbabasa ng mga address ng device sa hex. Ang Octal ay gumanap ng katulad na papel sa maagang pag-compute, kapag ang mga makina ay gumamit ng mga laki ng salita na nahahati sa tatlong bit, at lumalabas pa rin ito sa mga pahintulot ng file ng Unix, kung saan ang isang halaga tulad ng 755 ay nag-encode sa pagbasa, pagsulat, at pagpapatupad ng mga karapatan para sa may-ari, grupo, at iba pa.

Pag-convert sa pamamagitan ng Kamay: Dalawang Nagtrabahong Halimbawa

Ang pag-convert ng binary sa decimal sa pamamagitan ng kamay ay nagtuturo sa place-value idea na mas mahusay kaysa sa anumang kahulugan. Kunin ang 101101. Pagbasa mula sa kanan, ang mga posisyon ay nagkakahalaga ng 1, 2, 4, 8, 16, at 32. Ang mga digit ay 1, 0, 1, 1, 0, 1 mula sa kanan, kaya ang halaga ay 1 + 4 + 8 + 32 = 45. Ang pag-convert ng decimal sa binary2 ay napupunta sa ibang paraan. Para sa 45, ang mga natitira ay 1, 0, 1, 1, 0, 1, at ang pagbabasa ng mga ito pabalik ay nagbibigay ng 101101, na nagpapatunay sa unang conversion. Gumagana ang hexadecimal sa parehong paraan sa mga kapangyarihan na labing-anim: 1A3 ay nangangahulugang 1 beses 256, kasama ang A (10) beses 16, kasama ang 3, na 256 + 160 + 3 = 419.

Ang isang mabilis na shortcut ay nagkokonekta ng binary, octal, at hexadecimal nang hindi dumadaan sa decimal. Ipangkat ang mga binary digit sa tatlo mula sa kanan para sa octal, o sa apat para sa hexadecimal, pagkatapos ay i-convert ang bawat pangkat. Halimbawa, ang 101011110 ay nagiging 101 011 110 sa mga pangkat na octal, na 5 3 6, at 1 0101 1110 sa mga pangkat na hexadecimal, na 1 5 E, kaya ang halaga ay 536 sa octal at 15E sa hexadecimal. Madalas na nagkakamali ang mga mag-aaral dito: nalilimutang ilagay ang pinakakaliwang grupo ng mga nangungunang zero, at pagbabasa ng mga grupo mula sa kaliwa sa halip na sa kanan. Parehong nagbabago ang sagot, kaya palaging simulan ang pagpapangkat sa pinakakanang digit.

Mga Praktikal na Tip at Karaniwang Pagkakamali

Una, palaging sabihin ang base kapag nagbabahagi ng isang numero na maaaring hindi malabo: ang pagsulat ng 1010 lamang ay hindi nagsasabi sa sinuman kung ang ibig mong sabihin ay sampu o isang libo at sampu, kaya naman ang mga programmer ay sumusulat ng mga prefix gaya ng 0b1010 para sa binary at 0xFF para sa hexadecimal. Pangalawa, tandaan na ang mga nangungunang zero ay hindi nagbabago ng isang halaga, kaya ang 0001010 sa binary ay sampu pa rin; ang mga ito ay kadalasang idinaragdag lamang sa pad ng isang numero sa isang maayos na lapad, tulad ng walong bits. Pangatlo, ang converter na ito ay humahawak ng mga buong numero lamang. Ang mga fraction sa iba pang mga base, negatibong numero, at napakahabang input na lampas sa 64 na digit ay wala sa saklaw nito, at sasabihin ito sa iyo ng converter kaysa sa hulaan. Sa wakas, gumagana ang lahat sa iyong browser nang walang data na ipinadala kahit saan, kaya maaari mong i-convert ang mga sagot sa takdang-aralin, mga constant ng code, at mga halaga ng pahintulot nang pribado at nang madalas hangga't gusto mo.

Mga Madalas Itanong (FAQs)

Ano ang 255 sa binary, octal, at hexadecimal?
Ang 255 sa binary ay 11111111, sa octal ay 377, at sa hexadecimal ay FF. Ang lahat ng apat na form ay kumakatawan sa parehong halaga; tanging ang sistema ng pagbibilang ang nagbabago.
Bakit nagbibigay ng error ang binary 102?
Ginagamit lang ng binary ang mga digit na 0 at 1, kaya ilegal ang digit 2 sa base 2. Kung ang ibig mong sabihin ay ang decimal na numero na isang daan at dalawa, piliin muna ang decimal bilang input base.
Ano ang hexadecimal letters A hanggang F?
Ang hexadecimal ay nangangailangan ng labing-anim na digit, ngunit mayroon lamang kaming sampung numero, kaya ang mga titik A hanggang F ay kumakatawan sa mga halagang 10, 11, 12, 13, 14, at 15. Kaya naman ang ibig sabihin ng FF ay 15 beses 16 plus 15, na 255.
Paano ko mai-convert ang binary sa hexadecimal nang mabilis?
Pangkatin ang mga binary digit sa apat mula sa kanan, padding sa pinakakaliwang pangkat ng mga zero, pagkatapos ay i-convert ang bawat pangkat ng apat sa isang hex digit. Halimbawa, 11111111 mga pangkat bilang 1111 1111, na F F.
Pinangangasiwaan ba ng converter na ito ang mga negatibong numero o fraction?
Hindi. Kino-convert nito ang buong non-negative na integer hanggang 64 na digit. Ang mga negatibong numero at fraction sa ibang mga base ay nangangailangan ng ibang representasyon, tulad ng two's complement o isang fractional point, na hindi saklaw ng tool na ito.
