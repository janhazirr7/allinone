Paano Gamitin ang Converter ng Number Base

Ang mga computer, programmer, at electronics engineer ay palaging nagpapalit-palit sa pagitan ng mga number base: binary para sa hardware, octal para sa mas lumang sistema at file permission, decimal para sa pang-araw-araw na arithmetic, at hexadecimal bilang isang maikling shorthand para sa binary. Kinukuha ng converter na ito ang isang numero sa alinman sa apat na base na iyan at agad na ipinapakita ang lahat ng apat na value nang sabay, kaya hindi mo na kailangang mag-convert nang dalawang beses o magtaka kung ang isang digit ay legal sa base na iyong pinili.

  1. I-type ang iyong numeroIlagay ang value sa unang box, halimbawa 255, 1010, o FF. Mga buong hindi negatibong numero lamang; ang mga sign at decimal point ay hindi bahagi ng mga integer base na ito.
  2. Sabihin sa converter kung saang base ito naroroonPumili ng binary, octal, decimal, o hexadecimal mula sa dropdown. Mahalaga ito: ang 1010 ay nangangahulugang sampu sa binary ngunit isang libo at sampu sa decimal.
  3. Pindutin ang I-convert at basahin ang lahat ng apat na resultaAng binary, octal, decimal, at hexadecimal na mga value ay lumalabas nang magkakasama, na ang decimal value ay naka-highlight, upang makopya mo ang alinmang anyo na kailangan ng iyong code o homework.
  4. Kung may lumabas na error, suriin ang iyong mga digitAng bawat base ay nagpapahintulot lamang ng ilang digit. Ang binary ay nagpapahintulot lamang ng 0 at 1, kaya ang 102 ay tinatanggihan; ang octal ay nagpapahintulot ng 0 hanggang 7, kaya ang 89 ay tinatanggihan; ang hexadecimal ay nagpapahintulot ng 0 hanggang 9 at A hanggang F, kaya ang G ay tinatanggihan.

Ano ang Number Base, at Bakit Mayroon Tayong Higit sa Isa?

Ang isang number base, na tinatawag ding radix, ay simpleng kung ilang magkakaibang digit ang ginagamit ng isang sistema ng pagbibilang bago ito mag-carry over sa isang bagong lugar. Ang decimal, ang sistemang natutunan natin noong mga bata pa, ay gumagamit ng sampung digit (0 hanggang 9) dahil ang mga tao ay may sampung daliri. Ang bawat posisyon ay nagkakahalaga ng sampung beses ng nasa kanan nito: sa 255, ang mga digit ay nangangahulugang 2 daan + 5 sampu + 5 isa. Ang binary ay gumagamit lamang ng dalawang digit, 0 at 1, dahil ang hardware ng computer ay binubuo ng mga switch na naka-off o naka-on. Ang bawat binary na posisyon ay nagkakahalaga ng dalawang beses ng nasa kanan nito, kaya ang 1010 ay nangangahulugang 8 + 0 + 2 + 0 = 10. Ang octal ay gumagamit ng walong digit, 0 hanggang 7, at ang hexadecimal ay gumagamit ng labing-anim: 0 hanggang 9 kasama ang mga letrang A hanggang F para sa mga value na sampu hanggang labinlima.

Umiiral ang hexadecimal pangunahin bilang isang kaginhawahan para sa mga taong nagbabasa ng binary. Ang isang hexadecimal digit ay tumutugma sa eksaktong apat na binary digit, kaya ang isang mahabang binary string tulad ng 11111111 ay maayos na nagiging FF. Kaya nakikita mo ang hexadecimal saanman sa computing: ang mga color code sa web tulad ng #FF5733 ay talagang tatlong hexadecimal byte para sa pula, berde, at asul; ang mga memory address ay ipinapakita sa hex; at binabasa ng mga network engineer ang mga device address sa hex. Ang octal ay may katulad na papel sa maagang computing, nang ang mga makina ay gumamit ng mga word size na mahahati sa tatlong bit, at lumilitaw pa rin ito sa mga file permission ng Unix, kung saan ang isang value tulad ng 755 ay nag-e-encode ng read, write, at execute na mga karapatan para sa may-ari, grupo, at iba pa.

Pag-convert nang Manu-mano: Dalawang Halimbawang may Solusyon

Ang pag-convert ng binary sa decimal nang manu-mano ay nagtuturo ng ideya ng place-value nang mas mahusay kaysa sa anumang depinisyon. Kunin ang 101101. Sa pagbabasa mula sa kanan, ang mga posisyon ay nagkakahalaga ng 1, 2, 4, 8, 16, at 32. Ang mga digit ay 1, 0, 1, 1, 0, 1 mula sa kanan, kaya ang value ay 1 + 4 + 8 + 32 = 45. Ang pag-convert ng decimal sa binary ay kabaliktaran: paulit-ulit na hatiin sa 2 at itala ang mga natitira. Para sa 45, ang mga natitira ay 1, 0, 1, 1, 0, 1, at ang pagbabasa sa mga ito nang pabaliktad ay nagbibigay ng 101101, na nagkukumpirma sa unang conversion. Gumagana ang hexadecimal sa parehong paraan gamit ang mga power ng labing-anim: ang 1A3 ay nangangahulugang 1 beses 256, dagdag ang A (10) beses 16, dagdag ang 3, na 256 + 160 + 3 = 419.

Isang mabilis na shortcut ang nag-uugnay sa binary, octal, at hexadecimal nang hindi dumadaan sa decimal. Pangkatin ang mga binary digit nang tatlo mula sa kanan para sa octal, o nang apat para sa hexadecimal, pagkatapos ay i-convert ang bawat grupo. Halimbawa, ang 101011110 ay nagiging 101 011 110 sa mga grupo ng octal, na 5 3 6, at 1 0101 1110 sa mga grupo ng hexadecimal, na 1 5 E, kaya ang value ay 536 sa octal at 15E sa hexadecimal. Ang mga estudyante ay madalas na gumagawa ng dalawang pagkakamali dito: ang pagkalimot na lagyan ng leading zeros ang pinakakaliwang grupo, at ang pagbabasa ng mga grupo mula sa kaliwa sa halip na mula sa kanan. Ang pareho ay nagbabago sa sagot, kaya palaging magsimula sa pag-group sa pinakakanang digit.

Mga Praktikal na Tip at Karaniwang Pagkakamali

Una, palaging sabihin ang base kapag nagbabahagi ng isang numero na maaaring hindi malinaw: ang pagsulat ng 1010 nang mag-isa ay hindi nagsasabi sa sinuman kung ang ibig mong sabihin ay sampu o isang libo at sampu, kaya sumusulat ang mga programmer ng mga prefix tulad ng 0b1010 para sa binary at 0xFF para sa hexadecimal. Ikalawa, tandaan na ang mga leading zero ay hindi nagbabago sa isang value, kaya ang 0001010 sa binary ay sampu pa rin; madalas silang idinaragdag lamang upang punan ang isang numero sa isang maayos na lapad, tulad ng walong bit. Ikatlo, ang converter na ito ay humahawak lamang ng mga buong numero. Ang mga fraction sa ibang mga base, negatibong numero, at napakahabang input na lampas sa 64 digit ay wala sa saklaw nito, at sasabihin ito ng converter sa iyo sa halip na manghula. Sa wakas, ang lahat ay tumatakbo sa iyong browser nang walang datos na ipinapadala kahit saan, kaya maaari kang mag-convert ng mga sagot sa homework, mga constant sa code, at mga value ng permission nang pribado at nang madalas hangga't gusto mo.

Mga Madalas Itanong (FAQs)

Ano ang 255 sa binary, octal, at hexadecimal?
Ang 255 sa binary ay 11111111, sa octal ay 377, at sa hexadecimal ay FF. Ang lahat ng apat na anyo ay kumakatawan sa parehong value; ang sistema lamang ng pagbibilang ang nagbabago.
Bakit nagbibigay ng error ang binary na 102?
Gumagamit ang binary lamang ng mga digit na 0 at 1, kaya ang digit na 2 ay ilegal sa base 2. Kung ang ibig mong sabihin ay ang decimal na numero na isang daan at dalawa, piliin muna ang decimal bilang input base.
Ano ang mga hexadecimal na letrang A hanggang F?
Ang hexadecimal ay nangangailangan ng labing-anim na digit, ngunit mayroon lamang tayong sampung numeral, kaya ang mga letrang A hanggang F ay kumakatawan sa mga value na 10, 11, 12, 13, 14, at 15. Kaya ang FF ay nangangahulugang 15 beses 16 dagdag ang 15, na 255.
Paano ako magko-convert ng binary sa hexadecimal nang mabilis?
Pangkatin ang mga binary digit nang apat mula sa kanan, na nilalagyan ng mga zero ang pinakakaliwang grupo, pagkatapos ay i-convert ang bawat grupo ng apat sa isang hex digit. Halimbawa, ang 11111111 ay pinapangkat bilang 1111 1111, na F F.
Hinahawakan ba ng converter na ito ang mga negatibong numero o fraction?
Hindi. Nagko-convert ito ng mga buong hindi negatibong integer hanggang 64 digit. Ang mga negatibong numero at fraction sa ibang mga base ay nangangailangan ng ibang representasyon, tulad ng two's complement o isang fractional point, na hindi sakop ng tool na ito.
