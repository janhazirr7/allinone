Jak korzystać z formatera JSON

  1. Wklej swój JSONSkopiuj JSON z API, pliku konfiguracyjnego lub samouczka i wklej go do dużego pola.
  2. Wybierz działanieNaciśnij „Formatuj”, aby uczynić go czytelnym dzięki wcięciom, „Minifikuj”, aby skompresować go do jednej linii, albo „Tylko sprawdź”, aby sprawdzić go bez zmieniania.
  3. Przeczytaj błąd, jeśli jakiś jestJeśli JSON jest nieprawidłowy, narzędzie pokazuje dokładny błąd parsera prostymi słowami, więc wiesz, co naprawić.
  4. Kopiuj wynikUżyj „Kopiuj wynik”, aby przenieść sformatowany lub zminifikowany JSON z powrotem do swojego kodu, konfiguracji lub narzędzia API.

Czym jest JSON i dlaczego formatowanie ma znaczenie

JSON, skrót od JavaScript Object Notation, to najczęstszy sposób, w jaki komputery wymieniają dane strukturalne w sieci. API, pliki konfiguracyjne i wiele aplikacji mówi w JSON, ponieważ jest prosty do odczytania i łatwy do przetworzenia przez maszyny. Prawidłowy dokument JSON jest zbudowany z obiektów w nawiasach klamrowych, tablic w nawiasach kwadratowych, ciągów w podwójnych cudzysłowach, liczb oraz wartości true, false i null. Formatowanie nie zmienia znaczenia danych, ale zmienia to, jak łatwo człowiekowi je odczytać. Zminifikowany JSON, z usuniętymi wszystkimi spacjami, jest mniejszy i szybszy do wysłania przez sieć, dlatego używają go API, ale jest prawie niemożliwy do odczytania lub debugowania. Upiększony JSON, z dwuznakowymi wcięciami i jedną wartością na linię, jest większy, ale pozwala dostrzec brakujący przecinek lub zły nawias w kilka sekund.

Najczęstsze błędy JSON

  • Brakujące lub dodatkowe przecinki: każdy element obiektu lub tablicy oprócz ostatniego wymaga przecinka, a końcowy przecinek po ostatnim elemencie nie jest dozwolony w ścisłym JSON.
  • Pojedyncze cudzysłowy zamiast podwójnych: ciągi JSON muszą używać podwójnych cudzysłowów, mimo że kod JavaScript często pozwala na pojedyncze.
  • Cudzysłowy bez kluczy: klucze obiektów muszą być cytowanymi ciągami, więc {name: "Ana"} jest nieprawidłowe i musi być {"name": "Ana"}.
  • Komentarze: JSON nie pozwala na komentarze, więc linie zaczynające się od // przerwą przetwarzanie, nawet jeśli wyglądają nieszkodliwie.
  • Tekst końcowy lub wiele dokumentów: wklejenie dwóch obiektów JSON jeden po drugim jest nieprawidłowe; zawiń je w tablicę albo naprawiaj je po jednym.

Formatowanie a minifikacja: kiedy używać każdego

Używaj formatowania, gdy czytasz, debugujesz lub uczysz się na podstawie JSON, ponieważ wcięcia pokazują strukturę na pierwszy rzut oka i sprawiają, że zagnieżdżenie jest oczywiste. Używaj minifikacji, gdy musisz wkleić JSON do adresu URL, kompaktowego pola konfiguracyjnego, żądania testowego lub wiadomości, gdzie liczy się rozmiar, a czytelność nie. Używaj opcji „Tylko sprawdź”, gdy potrzebujesz tylko odpowiedzi tak lub nie, na przykład przed zapisaniem pliku konfiguracyjnego, ponieważ sprawdza JSON bez zastępowania oryginalnego tekstu. We wszystkich trzech przypadkach narzędzie najpierw przetwarza JSON, więc zminifikowany lub sformatowany wynik ma gwarantowaną poprawność; jeśli przetwarzanie się nie powiedzie, otrzymasz błąd zamiast cicho uszkodzonego wyniku, co jest dokładnie tym, czego chcesz przed wysłaniem kodu.

Prywatność i ograniczenia

Ten formater działa w całości w Twojej przeglądarce. Twój JSON nigdy nie jest przesyłany, rejestrowany ani udostępniany, co ma znaczenie, ponieważ JSON często zawiera klucze API, dane osobowe lub wewnętrzną konfigurację. Nigdy nie wklejaj sekretów do żadnego formatera online, któremu nie ufasz, i zmień każdy klucz, który przypadkowo ujawnisz. Narzędzie łatwo radzi sobie z typowymi odpowiedziami API i plikami konfiguracyjnymi, ale niezwykle duże dokumenty, liczące dziesiątki megabajtów, mogą działać wolno w karcie przeglądarki, ponieważ ich przetwarzanie i ponowne przekształcanie w ciąg zajmuje pamięć. Przestrzega też ścisłych zasad JSON, więc odrzuci dodatki w stylu JavaScript, takie jak końcowe przecinki, pojedyncze cudzysłowy i komentarze, mimo że niektóre narzędzia akceptują je luźno.

Często zadawane pytania (FAQ)

Czym różnią się formatowanie i minifikacja?
Formatowanie dodaje wcięcia i podziały linii, aby JSON był łatwy do odczytania przez człowieka. Minifikacja usuwa wszystkie zbędne spacje i podziały linii, aby JSON był jak najmniejszy do wysyłania lub przechowywania.
Dlaczego mój JSON kończy się błędem końcowego przecinka?
Ścisły JSON nie pozwala na przecinek po ostatnim elemencie obiektu lub tablicy. Usuń ten ostatni przecinek, a JSON zostanie przetworzony.
Czy mogę używać pojedynczych cudzysłowów w JSON?
Nie. Ciągi i klucze JSON muszą używać podwójnych cudzysłowów. Pojedyncze cudzysłowy działają w kodzie JavaScript, ale nie są poprawnym JSON i to narzędzie słusznie je odrzuci.
Czy dane mojego JSON są gdzieś przechowywane lub wysyłane?
Nie. Formatowanie i walidacja odbywają się w całości w Twojej przeglądarce, więc Twoje dane nigdy nie opuszczają Twojego urządzenia.
Czy formatowanie zmienia moje dane?
Nie. Formatowanie i minifikacja zmieniają tylko odstępy i podziały linii. Wartości, klucze i struktura pozostają dokładnie takie same, o ile JSON był poprawny od początku.
