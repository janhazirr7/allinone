Jak korzystać z formatera JSON

  2. Wybierz akcjęNaciśnij Format, aby był czytelny z wcięciami, Minifikuj, aby zmniejszyć go do jednej linii, lub Tylko sprawdź, aby sprawdzić bez zmiany.

Co to jest JSON i dlaczego formatowanie ma znaczenie

JSON, skrót od JavaScript Object Notation, to najpopularniejszy sposób wymiany danych strukturalnych przez komputery w Internecie. Interfejsy API, pliki konfiguracyjne i wiele aplikacji posługują się językiem JSON, ponieważ jest on czytelny i łatwy do analizy przez maszyny. Prawidłowy dokument JSON jest zbudowany z obiektów w nawiasach klamrowych, tablic w nawiasach kwadratowych, ciągów znaków w cudzysłowie, liczb oraz wartości true, false i null. Formatowanie nie zmienia znaczenia danych, ale zmienia łatwość ich odczytania przez człowieka. Zminifikowany kod JSON, po usunięciu wszystkich spacji, jest mniejszy i można go szybciej przesyłać przez sieć, dlatego interfejsy API go używają, ale jego odczytanie lub debugowanie jest prawie niemożliwe. Upiększony JSON, z wcięciem składającym się z dwóch spacji i jedną wartością w wierszu, jest większy, ale pozwala w ciągu kilku sekund wykryć brakujący przecinek lub nieprawidłowy nawias.

Najczęstsze błędy JSON

  • Brakujące lub dodatkowe przecinki: każdy element obiektu lub tablicy z wyjątkiem ostatniego wymaga przecinka, a przecinek końcowy po ostatnim elemencie nie jest dozwolony w ścisłym formacie JSON.
  • Pojedyncze cudzysłowy zamiast podwójnych cudzysłowów: ciągi JSON muszą używać podwójnych cudzysłowów, mimo że kod JavaScript często dopuszcza pojedyncze cudzysłowy.
  • Klucze bez cudzysłowu: klucze obiektów muszą być ciągami znaków w cudzysłowie, więc {name: "Ana"} jest nieprawidłowe i musi mieć wartość {"name": "Ana"}.
  • Komentarze: JSON nie pozwala na komentarze, więc linie zaczynające się od // przerywają analizę, nawet jeśli wyglądają nieszkodliwie.
  • Tekst końcowy lub wiele dokumentów: wklejanie dwóch obiektów JSON jeden po drugim jest nieprawidłowe; zawiń je w tablicę lub napraw je pojedynczo.

Formatowanie a minimalizowanie: kiedy używać każdego z nich

Używaj formatu podczas czytania, debugowania lub uczenia się z JSON, ponieważ wcięcia od razu ujawniają strukturę i sprawiają, że zagnieżdżanie jest oczywiste. Użyj Minify, gdy chcesz wkleić JSON do adresu URL, kompaktowego pola konfiguracyjnego, żądania testowego lub wiadomości, gdzie rozmiar ma znaczenie, a czytelność nie. Użyj opcji Validate Tylko wtedy, gdy potrzebujesz tylko odpowiedzi „tak” lub „nie”, na przykład przed zapisaniem pliku konfiguracyjnego, ponieważ sprawdza ona JSON bez zastępowania oryginalnego tekstu. We wszystkich trzech przypadkach narzędzie najpierw analizuje kod JSON, więc mamy pewność, że zminimalizowany lub sformatowany wynik będzie prawidłowy; jeśli parsowanie się nie powiedzie, zamiast cichego uszkodzonego wyniku pojawi się błąd, a właśnie tego chcesz przed wysyłką kodu.

Prywatność i ograniczenia

Ten program formatujący działa całkowicie w Twojej przeglądarce. Twój JSON nigdy nie jest przesyłany, rejestrowany ani udostępniany, co ma znaczenie, ponieważ JSON często zawiera klucze API, dane osobowe lub konfigurację wewnętrzną. Nigdy nie wklejaj sekretów do żadnego programu formatującego online, któremu nie ufasz, i nie obracaj dowolnego klucza, który przypadkowo odsłonisz. Narzędzie z łatwością obsługuje typowe odpowiedzi API i pliki konfiguracyjne, ale bardzo duże dokumenty (dziesiątki megabajtów) mogą działać wolno na karcie przeglądarki, ponieważ ich analizowanie i ponowne tworzenie ciągów wymaga pamięci. Przestrzega również ścisłych reguł JSON, więc odrzuca dodatki w stylu JavaScript, takie jak końcowe przecinki, pojedyncze cudzysłowy i komentarze, mimo że niektóre narzędzia akceptują je luźno.

Często zadawane pytania (FAQ)

Jaka jest różnica między Formatowaniem a Minify?
Format dodaje wcięcia i podziały wierszy, dzięki czemu kod JSON jest łatwy do odczytania przez ludzi. Minify usuwa wszystkie niepotrzebne spacje i podziały wierszy, dzięki czemu JSON jest tak mały, jak to możliwe do wysyłania lub przechowywania.
Dlaczego mój JSON kończy się niepowodzeniem z powodu błędu przecinka na końcu?
Ścisły kod JSON nie pozwala na wstawianie przecinka po ostatnim elemencie obiektu lub tablicy. Usuń ostatni przecinek, a JSON zostanie przeanalizowany.
Czy mogę używać pojedynczych cudzysłowów w JSON?
Nie. Ciągi i klucze JSON muszą być ujęte w cudzysłów. Pojedyncze cudzysłowy działają w kodzie JavaScript, ale nie są prawidłowym formatem JSON i to narzędzie poprawnie je odrzuci.
Czy moje dane JSON są gdziekolwiek przechowywane lub wysyłane?
Nie. Formatowanie i sprawdzanie poprawności odbywa się całkowicie w przeglądarce, więc Twoje dane nigdy nie opuszczają Twojego urządzenia.
Czy formatowanie zmienia moje dane?
Nie. Formatowanie i minimalizowanie zmieniają jedynie odstępy i podziały wierszy. Wartości, klucze i struktura pozostają dokładnie takie same, o ile kod JSON był od początku prawidłowy.
