Cara Menggunakan Pemformat JSON

  1. Tempel JSON AndaSalin JSON dari API, berkas konfigurasi, atau tutorial dan tempel ke kotak besar.
  2. Pilih tindakanTekan Format untuk membuatnya mudah dibaca dengan indentasi, Perkecil untuk menyusutkannya menjadi satu baris, atau Hanya Validasi untuk memeriksanya tanpa mengubahnya.
  3. Baca kesalahan jika adaJika JSON tidak valid, alat ini menampilkan kesalahan persis dari parser dengan kata-kata sederhana, sehingga Anda tahu apa yang harus diperbaiki.
  4. Salin hasilnyaGunakan Salin Keluaran untuk membawa JSON yang sudah diformat atau diminifikasi kembali ke kode, konfigurasi, atau alat API Anda.

Apa Itu JSON dan Mengapa Pemformatan Penting

JSON, singkatan dari JavaScript Object Notation, adalah cara paling umum komputer bertukar data terstruktur di web. API, berkas konfigurasi, dan banyak aplikasi semuanya berbicara JSON karena sederhana dibaca dan mudah diurai mesin. Dokumen JSON yang valid dibangun dari objek dalam kurung kurawal, array dalam kurung siku, string dalam tanda kutip ganda, angka, dan nilai true, false, dan null. Pemformatan tidak mengubah makna data, tetapi mengubah seberapa mudah data dibaca manusia. JSON yang diperkecil, dengan semua spasi dihapus, lebih kecil dan lebih cepat dikirim lewat jaringan, itulah sebabnya API menggunakannya, tetapi hampir mustahil dibaca atau di-debug. JSON yang dipercantik, dengan indentasi dua spasi dan satu nilai per baris, lebih besar tetapi memungkinkan Anda menemukan koma yang hilang atau kurung yang salah dalam hitungan detik.

Kesalahan JSON Paling Umum

  • Koma yang hilang atau berlebih: setiap item dalam objek atau array kecuali yang terakhir membutuhkan koma, dan koma di akhir setelah item terakhir tidak diizinkan dalam JSON ketat.
  • Tanda kutip tunggal, bukan ganda: string JSON harus menggunakan tanda kutip ganda, meski kode JavaScript sering mengizinkan tanda kutip tunggal.
  • Kunci tanpa tanda kutip: kunci objek harus berupa string bertanda kutip, sehingga {name: "Ana"} tidak valid dan harus menjadi {"name": "Ana"}.
  • Komentar: JSON tidak mengizinkan komentar, sehingga baris yang dimulai dengan // akan merusak parsing meski tampak tidak berbahaya.
  • Teks akhir atau beberapa dokumen: menempel dua objek JSON satu demi satu tidak valid; bungkus keduanya dalam array atau perbaiki satu per satu.

Memformat Versus Memperkecil: Kapan Menggunakan Masing-masing

Gunakan Format saat Anda membaca, men-debug, atau belajar dari JSON, karena indentasi mengungkapkan struktur sekilas dan membuat penyarangan tampak jelas. Gunakan Perkecil saat Anda perlu menempel JSON ke URL, kolom konfigurasi ringkas, permintaan uji, atau pesan di mana ukuran penting dan keterbacaan tidak penting. Gunakan Validasi Saja saat Anda hanya membutuhkan jawaban ya-atau-tidak, misalnya sebelum menyimpan berkas konfigurasi, karena fitur ini memeriksa JSON tanpa mengganti teks asli Anda. Dalam ketiga kasus itu alat ini pertama-tama mengurai JSON, sehingga hasil yang diminifikasi atau diformat dijamin valid; jika penguraian gagal, Anda mendapatkan kesalahan alih-alih keluaran rusak yang diam-diam, yang tepat seperti yang Anda inginkan sebelum mengirim kode.

Privasi dan Batasan

Pemformat ini berjalan sepenuhnya di peramban Anda. JSON Anda tidak pernah diunggah, dicatat, atau dibagikan, yang penting karena JSON sering berisi kunci API, data pribadi, atau konfigurasi internal. Jangan pernah menempel rahasia ke pemformat daring apa pun yang tidak Anda percayai, dan ganti kunci apa pun yang tanpa sengaja Anda paparkan. Alat ini menangani respons API umum dan berkas konfigurasi dengan mudah, tetapi dokumen yang sangat besar, puluhan megabita, bisa lambat dalam tab peramban karena mengurai dan mengubahnya kembali menjadi string membutuhkan memori. Alat ini juga mengikuti aturan JSON yang ketat, sehingga akan menolak tambahan gaya JavaScript seperti koma akhir, tanda kutip tunggal, dan komentar, meskipun beberapa alat menerimanya secara longgar.

Pertanyaan yang Sering Diajukan (FAQ)

Apa perbedaan antara Format dan Perkecil?
Format menambahkan indentasi dan jeda baris sehingga JSON mudah dibaca manusia. Perkecil menghapus semua spasi dan jeda baris yang tidak perlu sehingga JSON sekecil mungkin untuk dikirim atau disimpan.
Mengapa JSON saya gagal dengan kesalahan koma akhir?
JSON ketat tidak mengizinkan koma setelah item terakhir dalam objek atau array. Hapus koma terakhir itu dan JSON akan terurai.
Dapatkah saya menggunakan tanda kutip tunggal dalam JSON?
Tidak. String dan kunci JSON harus menggunakan tanda kutip ganda. Tanda kutip tunggal berfungsi dalam kode JavaScript, tetapi tidak valid dalam JSON dan alat ini akan menolaknya dengan benar.
Apakah data JSON saya disimpan atau dikirim ke mana pun?
Tidak. Pemformatan dan validasi berjalan sepenuhnya di peramban Anda, sehingga data Anda tidak pernah meninggalkan perangkat Anda.
Apakah pemformatan mengubah data saya?
Tidak. Pemformatan dan pemerkecilan hanya mengubah spasi dan jeda baris. Nilai, kunci, dan struktur tetap persis sama, selama JSON itu valid sejak awal.
