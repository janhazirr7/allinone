Apa Itu Base64 dan Mengapa Itu Ada

Base64 adalah cara untuk merepresentasikan byte apa pun, termasuk teks, gambar, dan file, hanya menggunakan 64 karakter aman: huruf kapital dan kecil, angka, plus dan garis miring, dengan tanda sama dengan sebagai bantalan di bagian akhir. Komputer sering kali perlu mengirim data biner melalui sistem yang hanya menangani teks biasa dengan aman, seperti header email, alamat web, bidang JSON, dan file konfigurasi. Byte mentah di tempat tersebut dapat rusak, salah dibaca, atau ditolak, sehingga Base64 menerjemahkannya menjadi teks yang tidak berubah selama perjalanan. Imbalannya adalah ukuran: keluaran Base64 sekitar sepertiga lebih besar dari data asli, karena tiga byte menjadi empat karakter. Hal ini dapat diterima untuk token, gambar kecil dan string pendek, namun boros untuk file yang sangat besar, itulah sebabnya Base64 tidak digunakan untuk streaming video atau download besar.

Mengapa Unicode Membutuhkan Perhatian Khusus

Bug umum pada alat Base64 sederhana adalah alat tersebut merusak teks non-Inggris. Browser lama berfungsi btoa dan atob hanya menangani karakter Latin, jadi kata seperti café, nama dalam bahasa Urdu atau Yunani, atau emoji dapat menghasilkan kesalahan atau sampah. Alat ini menghindari bug tersebut sepenuhnya dengan terlebih dahulu mengonversi teks Anda menjadi byte UTF-8 dengan TextEncoder, menyandikan byte tersebut, dan membalikkan proses dengan TextDecoder saat decode. Itu berarti Hola, Καλημέρα, مرحبا dan emoji tersenyum semuanya berjalan pulang-pergi dengan benar: menyandikannya, memecahkan kode hasilnya, dan Anda mendapatkan kembali teks aslinya. Jika alat lain memberi Anda karakter rusak untuk teks beraksen atau non-Latin, alat tersebut hampir pasti menggunakan btoa dan atob tanpa penanganan UTF-8, dan Anda harus beralih ke alat yang aman untuk Unicode seperti ini.

Penggunaan Umum dan Peringatan Keamanan

  • URL Data: gambar dan ikon kecil sering kali disematkan langsung di halaman web sebagai Base64, sehingga halaman tidak memerlukan file gambar terpisah.
  • Token API dan autentikasi dasar: nama pengguna, kata sandi, dan token terkadang dikodekan Base64 di header, namun ini bukan enkripsi dan harus selalu dilakukan melalui HTTPS.
  • Lampiran email: sistem email mengkodekan lampiran di Base64 sehingga file biner dapat berpindah melalui server email hanya teks.
  • Konfigurasi dan pengujian: pengembang mengkodekan string pendek untuk menguji API, menyimpan blob kecil di JSON, dan membandingkan nilai tanpa mengkhawatirkan karakter khusus.

Privasi dan Batasan

Base64 adalah pengkodean, bukan enkripsi. Siapa pun yang melihat string Base64 dapat memecahkan kodenya dalam hitungan detik, jadi jangan pernah menggunakannya untuk menyembunyikan kata sandi, kunci rahasia, atau informasi pribadi, dan jangan pernah menganggapnya aman. Alat ini berjalan sepenuhnya di browser Anda, sehingga teks Anda tidak pernah diunggah atau disimpan, namun hasilnya sendiri masih dapat dibaca oleh siapa pun yang Anda bagikan. Alat ini menerima Base64 standar dan varian aman-URL yang menggunakan tanda minus dan garis bawah, bukan tanda plus dan garis miring, dan alat ini menoleransi jeda baris dan bantalan yang hilang, sehingga dapat memaafkan string yang disalin dari email. Input yang sangat besar mungkin lambat di tab browser, jadi untuk file multi-megabyte gunakan alat desktop saja.

Pertanyaan yang Sering Diajukan (FAQ)

Apakah enkripsi Base64?
Tidak. Base64 hanya pengkodean, perubahan format yang dapat dibalik. Siapa pun dapat memecahkan kode string Base64 secara instan, jadi string tersebut tidak boleh digunakan untuk menyembunyikan kata sandi atau rahasia.
Mengapa teks beraksen saya pecah di beberapa alat Base64?
Alat tersebut menggunakan bare btoa dan atob, yang hanya menangani karakter Latin. Alat ini mengonversi teks menjadi UTF-8 byte terlebih dahulu, sehingga huruf beraksen, Yunani, Urdu, dan emoji semuanya berfungsi dengan benar.
Mengapa keluaran Base64 lebih panjang dari teks saya?
Base64 mengubah setiap 3 byte menjadi 4 karakter, sehingga keluarannya sekitar 33 persen lebih besar. Itu adalah harga normal untuk membuat data biner aman untuk sistem hanya teks.
Untuk apa tanda sama dengan di akhir?
Tanda sama dengan adalah bantalan. Mereka mengisi grup terakhir menjadi empat karakter ketika panjang input bukan kelipatan tiga, sehingga decoder mengetahui dengan tepat di mana data berakhir.
Apakah teks saya dikirim ke server?
Tidak. Pengkodean dan penguraian kode dijalankan sepenuhnya di browser Anda dan tidak ada yang Anda masukkan yang keluar dari perangkat Anda.
