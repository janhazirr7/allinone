איך משתמשים במעצב JSON

  1. הדביקו את ה-JSON שלכםהעתיקו JSON מ-API, מקובץ תצורה או ממדריך והדביקו אותו לתיבה הגדולה.
  2. בחרו פעולהלחצו על עיצוב כדי להפוך אותו לקריא עם הזחה, כיווץ כדי לכווץ אותו לשורה אחת, או אימות בלבד כדי לבדוק אותו בלי לשנות אותו.
  3. קראו את השגיאה אם יש אחתאם ה-JSON אינו תקף, הכלי מציג את השגיאה המדויקת מהמנתח במילים פשוטות, כדי שתדעו מה לתקן.
  4. העתיקו את התוצאההשתמשו בהעתק פלט כדי לקחת את ה-JSON המעוצב או המכווץ בחזרה לקוד, לתצורה או לכלי ה-API שלכם.

מהו JSON ולמה עיצוב חשוב

JSON, קיצור של JavaScript Object Notation, הוא הדרך הנפוצה ביותר שמחשבים מחליפים בה נתונים מובנים באינטרנט. APIs, קבצי תצורה ואפליקציות רבות מדברות JSON כי הוא פשוט לקריאה וקל למכונות לניתוח. מסמך JSON תקף בנוי מאובייקטים בסוגריים מסולסלים, מערכים בסוגריים מרובעים, מחרוזות במרכאות כפולות, מספרים, והערכים true, false ו-null. עיצוב לא משנה את משמעות הנתונים, אבל הוא משנה כמה קל לבן אדם לקרוא אותם. JSON מכווץ, עם כל הרווחים מוסרים, קטן ומהיר יותר לשליחה ברשת, ולכן APIs משתמשים בו, אבל כמעט בלתי אפשרי לקרוא או לדבג אותו. JSON מיופה, עם הזחה של שני רווחים וערך אחד לשורה, גדול יותר אבל מאפשר לכם לזהות פסיק חסר או סוגר שגוי בשניות.

שגיאות ה-JSON הנפוצות ביותר

  • פסיקים חסרים או נוספים: כל פריט באובייקט או מערך חוץ מהאחרון צריך פסיק, ופסיק נגרר אחרי הפריט האחרון אינו מותר ב-JSON קפדני.
  • מרכאות בודדות במקום כפולות: מחרוזות JSON חייבות להשתמש במרכאות כפולות, למרות שקוד JavaScript לעיתים קרובות מאפשר מרכאות בודדות.
  • מפתחות לא מצוטטים: מפתחות אובייקט חייבים להיות מחרוזות מצוטטות, ולכן {name: "Ana"} אינו תקף וחייב להיות {"name": "Ana"}.
  • הערות: JSON לא מאפשר הערות, ולכן שורות המתחילות ב-// ישברו ניתוח גם אם הן נראות לא מזיקות.
  • טקסט נגרר או מסמכים מרובים: הדבקת שני אובייקטי JSON אחד אחרי השני אינה תקפה; עטפו אותם במערך או תקנו אותם אחד בכל פעם.

עיצוב מול כיווץ: מתי להשתמש בכל אחד

השתמשו בעיצוב כשאתם קוראים, מדבגים או לומדים מ-JSON, כי הזחה חושפת את המבנה במבט חטוף והופכת קינון לברור. השתמשו בכיווץ כשאתם צריכים להדביק JSON לכתובת URL, לשדה תצורה קומפקטי, לבקשת בדיקה או להודעה שבה הגודל חשוב והקריאות לא. השתמשו באימות בלבד כשאתם צריכים רק תשובת כן-או-לא, למשל לפני שמירת קובץ תצורה, כי הוא בודק את ה-JSON בלי להחליף את הטקסט המקורי שלכם. בכל שלושת המקרים הכלי קודם מנתח את ה-JSON, ולכן תוצאה מכווצת או מעוצבת מובטחת כתקפה; אם הניתוח נכשל, תקבלו שגיאה במקום פלט שבור בשקט, וזה בדיוק מה שאתם רוצים לפני משלוח קוד.

פרטיות ומגבלות

מעצב זה פועל במלואו בדפדפן שלכם. ה-JSON שלכם לעולם לא מועלה, נרשם או משותף, מה שחשוב כי JSON לעיתים קרובות מכיל מפתחות API, נתונים אישיים או תצורה פנימית. לעולם אל תדביקו סודות במעצב מקוון שאינכם סומכים עליו, והחליפו כל מפתח שחשפתם בטעות. הכלי מטפל בתגובות API טיפוסיות וקבצי תצורה בקלות, אבל מסמכים גדולים מאוד, עשרות מגה-בייטים, עשויים להיות איטיים בלשונית דפדפן כי ניתוח והמרה חוזרת למחרוזת לוקחים זיכרון. הוא גם עוקב אחר כללי JSON קפדניים, ולכן הוא ידחה תוספות בסגנון JavaScript כמו פסיקים נגררים, מרכאות בודדות והערות, למרות שכמה כלים מקבלים אותן בחופשיות.

שאלות נפוצות

מה ההבדל בין עיצוב לכיווץ?
עיצוב מוסיף הזחה ושבירות שורות כדי ש-JSON יהיה קל לקריאה לבני אדם. כיווץ מסיר את כל הרווחים ושבירות השורות המיותרים כדי ש-JSON יהיה קטן ככל האפשר לשליחה או אחסון.
למה ה-JSON שלי נכשל עם שגיאת פסיק נגרר?
JSON קפדני לא מאפשר פסיק אחרי הפריט האחרון באובייקט או מערך. הסירו את הפסיק האחרון הזה וה-JSON ינותח.
האם אפשר להשתמש במרכאות בודדות ב-JSON?
לא. מחרוזות ומפתחות JSON חייבים להשתמש במרכאות כפולות. מרכאות בודדות עובדות בקוד JavaScript, אבל הן לא JSON תקף וכלי זה ידחה אותן בצדק.
האם נתוני ה-JSON שלי נשמרים או נשלחים לאיפשהו?
לא. עיצוב ואימות פועלים במלואו בדפדפן שלכם, ולכן הנתונים שלכם לעולם לא עוזבים את המכשיר שלכם.
האם עיצוב משנה את הנתונים שלי?
לא. עיצוב וכיווץ משנים רק רווחים ושבירות שורות. הערכים, המפתחות והמבנה נשארים בדיוק אותו דבר, כל עוד ה-JSON היה תקף מלכתחילה.
