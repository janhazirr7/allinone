כיצד להשתמש בפורמט JSON

  1. הדבק את ה-JSON שלךהעתק JSON מ-API, קובץ תצורה או מדריך והדבק אותו בתיבה הגדולה.
  2. בחר פעולההקש על עיצוב כדי להפוך אותו לקריאה עם הזחה, הקטן כדי לכווץ אותו לשורה אחת, או אימות בלבד כדי לבדוק אותו מבלי לשנות אותו.
  3. קרא את השגיאה אם ​​יש כזואם ה-JSON לא חוקי, הכלי מציג את השגיאה המדויקת מהמנתח במילים פשוטות, כדי שתדע מה לתקן.
  4. העתק את התוצאההשתמש ב-Copy Output כדי להחזיר את ה-JSON המעוצב או הממוזער לכלי הקוד, התצורה או ה-API שלך.

מה זה JSON ומדוע העיצוב חשוב

JSON, קיצור של JavaScript Object Notation, היא הדרך הנפוצה ביותר שבה מחשבים מחליפים נתונים מובנים באינטרנט. ממשקי API, קבצי תצורה ואפליקציות רבות מדברים כולם ב-JSON מכיוון שהוא פשוט לקריאה וקל למכונות לנתח. מסמך JSON חוקי בנוי מאובייקטים בסוגריים מסולסלים, מערכים בסוגריים מרובעים, מחרוזות במירכאות כפולות, מספרים והערכים true, false ו-null. עיצוב לא משנה את משמעות הנתונים, אבל הוא משנה כמה קל לאדם לקרוא. JSON ממוזער, עם הסרת כל הרווחים, הוא קטן ומהיר יותר לשליחה ברשת, וזו הסיבה שממשקי API משתמשים בו, אבל זה כמעט בלתי אפשרי לקרוא או לנפות באגים. JSON מיופה, עם הזחה של שני רווחים וערך אחד בכל שורה, גדול יותר אבל מאפשר לך לזהות פסיק חסר או סוגר שגוי בתוך שניות.

שגיאות JSON הנפוצות ביותר

  • פסיקים חסרים או מיותרים: כל פריט באובייקט או במערך מלבד האחרון צריך פסיק, ופסיק אחרי הפריט האחרון אסור ב-JSON קפדני.
  • מרכאות בודדות במקום מרכאות כפולות: מחרוזות JSON חייבות להשתמש במירכאות כפולות, למרות שקוד JavaScript מאפשר לרוב מרכאות בודדות.
  • מפתחות ללא מרכאות: מפתחות אובייקט חייבים להיות מחרוזות במירכאות, לכן {name: "Ana"} אינו חוקי וחייב להיות {"name": "Ana"}.
  • הערות: JSON אינו מאפשר הערות, ולכן שורות המתחילות ב-// ישברו את הניתוח גם אם הן נראות לא מזיקות.
  • טקסט נגרר או מסמכים מרובים: הדבקת שני אובייקטי JSON בזה אחר זה אינה חוקית; עטפו אותם במערך או תקנו אותם אחד בכל פעם.

עיצוב לעומת צמצום: מתי להשתמש בכל אחד

השתמש בפורמט כשאתה קורא, מנקה באגים או לומד מ-JSON, מכיוון שהזחה חושפת את המבנה במבט חטוף והופכת את הקינון לברור. השתמש ב-Minify כאשר אתה צריך להדביק JSON בכתובת URL, שדה תצורה קומפקטי, בקשת בדיקה או הודעה שבה הגודל חשוב והקריאות לא. השתמש ב- Validate Only כאשר אתה צריך רק תשובה של כן או לא, למשל לפני שמירת קובץ תצורה, מכיוון שהוא בודק את ה-JSON מבלי להחליף את הטקסט המקורי שלך. בכל שלושת המקרים הכלי מנתח תחילה את ה-JSON, כך שתוצאה ממוזערת או מעוצבת מובטחת להיות תקפה; אם הניתוח נכשל, אתה מקבל שגיאה במקום פלט שבור בשקט, וזה בדיוק מה שאתה רוצה לפני קוד המשלוח.

פרטיות ומגבלות

הפורמט הזה פועל כולו בדפדפן שלך. ה-JSON שלך לעולם אינו מועלה, נרשם או משותף, מה שחשוב מכיוון ש-JSON מכיל לעתים קרובות מפתחות API, נתונים אישיים או תצורה פנימית. לעולם אל תדביק סודות בפורמט מקוון שאתה לא סומך עליו, וסובב כל מפתח שאתה חושף בטעות. הכלי מטפל בקלות בתגובות API וקבצי תצורה טיפוסיים, אך מסמכים גדולים במיוחד, עשרות מגה-בייט, עשויים להיות איטיים בכרטיסיית דפדפן מכיוון שניתוח והמחרוזות מחדש דורשות זיכרון. הוא גם עוקב אחר כללי JSON קפדניים, כך שהוא ידחה תוספות בסגנון JavaScript כמו פסיקים נגררים, ציטוטים בודדים והערות, למרות שחלק מהכלים מקבלים אותם באופן רופף.

שאלות נפוצות (שאלות נפוצות)

מה ההבדל בין פורמט ל-Minify?
הפורמט מוסיף הזחה ומעברי שורות כך ש-JSON קל לבני אדם לקריאה. Minify מסיר את כל הרווחים ומעברי השורות המיותרים כך ש-JSON יהיה קטן ככל האפשר לשליחה או אחסון.
מדוע ה-JSON שלי נכשל עם שגיאת פסיק נגררת?
Strict JSON אינו מאפשר פסיק אחרי הפריט האחרון באובייקט או במערך. הסר את הפסיק האחרון וה-JSON ינתח.
האם אוכל להשתמש במירכאות בודדות ב-JSON?
לא. מחרוזות ומפתחות JSON חייבים להשתמש במירכאות כפולות. ציטוטים בודדים עובדים בקוד JavaScript, אבל הם אינם JSON חוקיים והכלי הזה ידחה אותם בצורה נכונה.
האם נתוני ה-JSON שלי מאוחסנים או נשלחים למקום כלשהו?
לא. העיצוב והאימות פועלים לחלוטין בדפדפן שלך, כך שהנתונים שלך לעולם לא יוצאים מהמכשיר שלך.
האם העיצוב משנה את הנתונים שלי?
לא. עיצוב וצמצום משנים רק את המרווחים ואת מעברי השורות. הערכים, המפתחות והמבנה נשארים זהים, כל עוד ה-JSON היה תקף מלכתחילה.
