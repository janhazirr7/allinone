JSON फ़ॉर्मेटर का उपयोग कैसे करें

  1. अपना JSON पेस्ट करेंAPI, कॉन्फ़िग फ़ाइल या ट्यूटोरियल से JSON कॉपी करें और बड़े बॉक्स में पेस्ट करें।
  2. कोई क्रिया चुनेंइसे इंडेंटेशन के साथ पढ़ने योग्य बनाने के लिए "फ़ॉर्मेट करें" दबाएँ, इसे एक पंक्ति में सिकोड़ने के लिए "मिनिफ़ाई करें", या इसे बदले बिना जाँचने के लिए "सिर्फ़ मान्य करें"।
  3. अगर कोई त्रुटि है तो उसे पढ़ेंअगर JSON अमान्य है, तो टूल पार्सर से सटीक त्रुटि सरल शब्दों में दिखाता है, ताकि आप जान सकें कि क्या ठीक करना है।
  4. परिणाम कॉपी करेंफ़ॉर्मेट या मिनिफ़ाइड JSON को अपने कोड, कॉन्फ़िग या API टूल में वापस ले जाने के लिए "आउटपुट कॉपी करें" का उपयोग करें।

JSON क्या है और फ़ॉर्मेटिंग क्यों मायने रखती है

JSON, JavaScript Object Notation का संक्षिप्त रूप, वेब पर कंप्यूटरों द्वारा संरचित डेटा विनिमय का सबसे आम तरीका है। API, कॉन्फ़िगरेशन फ़ाइलें और कई ऐप सभी JSON बोलते हैं क्योंकि इसे पढ़ना सरल है और मशीनों के लिए पार्स करना आसान है। वैध JSON दस्तावेज़ घुंघराले कोष्ठकों में ऑब्जेक्ट, वर्गाकार कोष्ठकों में ऐरे, दोहरे उद्धरण चिह्नों में स्ट्रिंग, संख्याओं, और true, false व null मानों से बना होता है। फ़ॉर्मेटिंग डेटा का अर्थ नहीं बदलती, लेकिन यह बदलती है कि मनुष्य के लिए इसे पढ़ना कितना आसान है। मिनिफ़ाइड JSON, सभी स्पेस हटाकर, छोटा और नेटवर्क पर भेजने में तेज़ होता है, इसलिए API इसका उपयोग करते हैं, लेकिन इसे पढ़ना या डीबग करना लगभग असंभव है। सुंदर किया गया JSON, दो-स्पेस इंडेंटेशन और प्रति पंक्ति एक मान के साथ, बड़ा होता है लेकिन आपको सेकंडों में गायब अल्पविराम या ग़लत कोष्ठक पहचानने देता है।

सबसे आम JSON त्रुटियाँ

  • गायब या अतिरिक्त अल्पविराम: ऑब्जेक्ट या ऐरे में आख़िरी को छोड़कर हर आइटम को अल्पविराम चाहिए होता है, और आख़िरी आइटम के बाद पिछला अल्पविराम सख़्त JSON में अनुमत नहीं है।
  • दोहरे उद्धरण चिह्नों के बजाय एकल उद्धरण चिह्न: JSON स्ट्रिंगों को दोहरे उद्धरण चिह्नों का उपयोग करना चाहिए, भले ही JavaScript कोड अक्सर एकल उद्धरण चिह्नों की अनुमति देता है।
  • बिना उद्धरण वाली कुंजियाँ: ऑब्जेक्ट कुंजियाँ उद्धृत स्ट्रिंग होनी चाहिए, इसलिए {name: "Ana"} अमान्य है और {"name": "Ana"} होना चाहिए।
  • टिप्पणियाँ: JSON टिप्पणियों की अनुमति नहीं देता, इसलिए // से शुरू होने वाली पंक्तियाँ पार्सिंग तोड़ देंगी भले ही वे हानिरहित दिखें।
  • पिछला पाठ या कई दस्तावेज़: दो JSON ऑब्जेक्ट एक के बाद एक पेस्ट करना अमान्य है; उन्हें ऐरे में लपेटें या एक बार में एक ठीक करें।

फ़ॉर्मेट बनाम मिनिफ़ाई: प्रत्येक का उपयोग कब करें

जब आप JSON पढ़ रहे, डीबग कर रहे या उससे सीख रहे हैं तो "फ़ॉर्मेट करें" का उपयोग करें, क्योंकि इंडेंटेशन एक नज़र में संरचना दिखाता है और नेस्टिंग स्पष्ट बनाता है। जब आपको JSON को URL, कॉम्पैक्ट कॉन्फ़िग फ़ील्ड, परीक्षण अनुरोध या संदेश में पेस्ट करना हो जहाँ आकार मायने रखता है और पठनीयता नहीं, तो "मिनिफ़ाई करें" का उपयोग करें। जब आपको सिर्फ़ हाँ-या-ना उत्तर चाहिए, उदाहरण के लिए कॉन्फ़िग फ़ाइल सहेजने से पहले, तो "सिर्फ़ मान्य करें" का उपयोग करें, क्योंकि यह आपके मूल पाठ को बदले बिना JSON जाँचता है। तीनों मामलों में टूल पहले JSON पार्स करता है, इसलिए मिनिफ़ाइड या फ़ॉर्मेट परिणाम वैध होने की गारंटी है; अगर पार्सिंग विफल होती है, तो आपको चुपचाप टूटे आउटपुट के बजाय त्रुटि मिलती है, जो कोड भेजने से पहले आप बिल्कुल चाहते हैं।

निजता और सीमाएँ

यह फ़ॉर्मेटर पूरी तरह आपके ब्राउज़र में चलता है। आपका JSON कभी अपलोड, लॉग या साझा नहीं किया जाता, जो मायने रखता है क्योंकि JSON में अक्सर API कुंजियाँ, व्यक्तिगत डेटा या आंतरिक कॉन्फ़िगरेशन होता है। किसी भी ऑनलाइन फ़ॉर्मेटर में जिसे आप भरोसा नहीं करते, कभी रहस्य पेस्ट न करें, और गलती से उजागर की गई किसी भी कुंजी को बदलें। टूल सामान्य API प्रतिक्रियाओं और कॉन्फ़िग फ़ाइलों को आसानी से संभालता है, लेकिन बहुत बड़े दस्तावेज़, दसियों मेगाबाइट, ब्राउज़र टैब में धीमे हो सकते हैं क्योंकि उन्हें पार्स और फिर से स्ट्रिंग करना मेमोरी लेता है। यह सख़्त JSON नियमों का भी पालन करता है, इसलिए यह ट्रेलिंग अल्पविराम, एकल उद्धरण चिह्न और टिप्पणियों जैसे JavaScript-शैली के अतिरिक्त को अस्वीकार करेगा, भले ही कुछ टूल उन्हें ढीले ढंग से स्वीकार करते हैं।

अक्सर पूछे जाने वाले प्रश्न (FAQs)

फ़ॉर्मेट और मिनिफ़ाई में क्या अंतर है?
फ़ॉर्मेट इंडेंटेशन और लाइन ब्रेक जोड़ता है ताकि JSON मनुष्यों के लिए पढ़ना आसान हो। मिनिफ़ाई सभी अनावश्यक स्पेस और लाइन ब्रेक हटा देता है ताकि JSON भेजने या स्टोर करने के लिए जितना संभव हो उतना छोटा हो।
मेरा JSON ट्रेलिंग अल्पविराम त्रुटि के साथ क्यों विफल होता है?
सख़्त JSON ऑब्जेक्ट या ऐरे में आख़िरी आइटम के बाद अल्पविराम की अनुमति नहीं देता। वह अंतिम अल्पविराम हटाएँ और JSON पार्स हो जाएगा।
क्या मैं JSON में एकल उद्धरण चिह्नों का उपयोग कर सकता हूँ?
नहीं। JSON स्ट्रिंग और कुंजियों को दोहरे उद्धरण चिह्नों का उपयोग करना चाहिए। एकल उद्धरण चिह्न JavaScript कोड में काम करते हैं, लेकिन वे वैध JSON नहीं हैं और यह टूल उन्हें सही ढंग से अस्वीकार करेगा।
क्या मेरा JSON डेटा कहीं स्टोर या भेजा जाता है?
नहीं। फ़ॉर्मेट और मान्यता पूरी तरह आपके ब्राउज़र में चलती है, इसलिए आपका डेटा कभी आपकी डिवाइस को नहीं छोड़ता।
क्या फ़ॉर्मेटिंग मेरा डेटा बदलती है?
नहीं। फ़ॉर्मेट और मिनिफ़ाई सिर्फ़ स्पेसिंग और लाइन ब्रेक बदलते हैं। मान, कुंजियाँ और संरचना बिल्कुल समान रहते हैं, जब तक JSON शुरुआत में वैध था।
