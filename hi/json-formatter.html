JSON फ़ॉर्मेटर का उपयोग कैसे करें

  1. अपना JSON चिपकाएँकिसी एपीआई, कॉन्फिग फ़ाइल या ट्यूटोरियल से JSON कॉपी करें और बड़े बॉक्स में पेस्ट करें।
  2. कोई क्रिया चुनेंइसे इंडेंटेशन के साथ पढ़ने योग्य बनाने के लिए फ़ॉर्मेट दबाएँ, इसे एक पंक्ति में सिकोड़ने के लिए छोटा करें, या इसे बदले बिना जाँचने के लिए केवल मान्य करें दबाएँ।
  3. यदि कोई त्रुटि है तो उसे पढ़ेंयदि JSON अमान्य है, तो टूल स्पष्ट शब्दों में पार्सर से सटीक त्रुटि दिखाता है, ताकि आप जान सकें कि क्या ठीक करना है।
  4. परिणाम कॉपी करेंफ़ॉर्मेट किए गए या छोटे किए गए JSON को अपने कोड, कॉन्फ़िगरेशन या एपीआई टूल पर वापस ले जाने के लिए कॉपी आउटपुट का उपयोग करें।

JSON क्या है और फ़ॉर्मेटिंग क्यों मायने रखती है

JSON, जावास्क्रिप्ट ऑब्जेक्ट नोटेशन के लिए संक्षिप्त, कंप्यूटर द्वारा वेब पर संरचित डेटा का आदान-प्रदान करने का सबसे आम तरीका है। एपीआई, कॉन्फ़िगरेशन फ़ाइलें और कई ऐप्स सभी JSON बोलते हैं क्योंकि इसे पढ़ना आसान है और मशीनों के लिए इसे पार्स करना आसान है। एक वैध JSON दस्तावेज़ घुंघराले ब्रेसिज़ में वस्तुओं, वर्गाकार कोष्ठकों में सरणियों, दोहरे उद्धरण चिह्नों में स्ट्रिंग्स, संख्याओं और सही, गलत और शून्य मानों से बनाया गया है। फ़ॉर्मेटिंग से डेटा का अर्थ नहीं बदलता है, बल्कि यह बदलता है कि किसी इंसान के लिए इसे पढ़ना कितना आसान है। मिनिफाइड JSON, सभी रिक्त स्थान हटा दिए जाने के साथ, नेटवर्क पर भेजने के लिए छोटा और तेज़ है, यही कारण है कि एपीआई इसका उपयोग करते हैं, लेकिन इसे पढ़ना या डीबग करना लगभग असंभव है। दो-स्पेस इंडेंटेशन और प्रति पंक्ति एक मान के साथ सुशोभित JSON बड़ा है, लेकिन आपको सेकंडों में गायब अल्पविराम या गलत ब्रैकेट का पता लगाने देता है।

सबसे आम JSON त्रुटियाँ

  • गुम या अतिरिक्त अल्पविराम: किसी ऑब्जेक्ट या सरणी में अंतिम आइटम को छोड़कर प्रत्येक आइटम को अल्पविराम की आवश्यकता होती है, और सख्त JSON में अंतिम आइटम के बाद अनुगामी अल्पविराम की अनुमति नहीं है।
  • डबल कोट्स के बजाय सिंगल कोट्स: JSON स्ट्रिंग्स को डबल कोट्स का उपयोग करना चाहिए, भले ही जावास्क्रिप्ट कोड अक्सर सिंगल कोट्स की अनुमति देता है।
  • गैर-उद्धृत कुंजियाँ: ऑब्जेक्ट कुंजियाँ स्ट्रिंग्स में उद्धृत की जानी चाहिए, इसलिए {नाम: "एना"} अमान्य है और इसे {"नाम": "एना"} होना चाहिए।
  • टिप्पणियाँ: JSON टिप्पणियों की अनुमति नहीं देता है, इसलिए // से शुरू होने वाली पंक्तियाँ हानिरहित दिखने पर भी पार्सिंग को तोड़ देंगी।
  • अनुगामी पाठ या एकाधिक दस्तावेज़: दो JSON ऑब्जेक्ट को एक के बाद एक चिपकाना अमान्य है; उन्हें एक सरणी में लपेटें या एक-एक करके ठीक करें।

फ़ॉर्मेटिंग बनाम लघुकरण: प्रत्येक का उपयोग कब करें

जब आप पढ़ रहे हों, डिबगिंग कर रहे हों या JSON से सीख रहे हों तो फ़ॉर्मेट का उपयोग करें, क्योंकि इंडेंटेशन एक नज़र में संरचना को प्रकट करता है और नेस्टिंग को स्पष्ट करता है। जब आपको JSON को URL, कॉम्पैक्ट कॉन्फ़िगरेशन फ़ील्ड, परीक्षण अनुरोध या संदेश में पेस्ट करने की आवश्यकता होती है, जहां आकार मायने रखता है और पठनीयता नहीं, तो Minify का उपयोग करें। केवल मान्य करें का उपयोग करें जब आपको केवल हां-या-नहीं उत्तर की आवश्यकता हो, उदाहरण के लिए कॉन्फ़िगरेशन फ़ाइल को सहेजने से पहले, क्योंकि यह आपके मूल पाठ को प्रतिस्थापित किए बिना JSON की जांच करता है। तीनों मामलों में उपकरण पहले JSON को पार्स करता है, इसलिए एक छोटा या स्वरूपित परिणाम मान्य होने की गारंटी है; यदि पार्सिंग विफल हो जाती है, तो आपको चुपचाप टूटे हुए आउटपुट के बजाय एक त्रुटि मिलती है, जो बिल्कुल वही है जो आप शिपिंग कोड से पहले चाहते हैं।

गोपनीयता और सीमाएँ

यह फ़ॉर्मेटर पूरी तरह से आपके ब्राउज़र में चलता है। आपका JSON कभी भी अपलोड, लॉग या साझा नहीं किया जाता है, जो मायने रखता है क्योंकि JSON में अक्सर एपीआई कुंजी, व्यक्तिगत डेटा या आंतरिक कॉन्फ़िगरेशन होता है। कभी भी किसी ऐसे ऑनलाइन फ़ॉर्मेटर में रहस्य न चिपकाएँ जिस पर आपको भरोसा न हो, और गलती से उजागर हुई किसी भी कुंजी को घुमाएँ। उपकरण विशिष्ट एपीआई प्रतिक्रियाओं और कॉन्फ़िगरेशन फ़ाइलों को आसानी से संभालता है, लेकिन बहुत बड़े दस्तावेज़, दसियों मेगाबाइट, ब्राउज़र टैब में धीमे हो सकते हैं क्योंकि उन्हें पार्स करने और फिर से स्ट्रिंग करने में मेमोरी लगती है। यह सख्त JSON नियमों का भी पालन करता है, इसलिए यह जावास्क्रिप्ट-शैली के अतिरिक्त जैसे अनुगामी अल्पविराम, एकल उद्धरण और टिप्पणियों को अस्वीकार कर देगा, भले ही कुछ उपकरण उन्हें शिथिल रूप से स्वीकार करते हों।

अक्सर पूछे जाने वाले प्रश्न (एफएक्यू)

फॉर्मेट और मिनिफाई में क्या अंतर है?
प्रारूप इंडेंटेशन और लाइन ब्रेक जोड़ता है ताकि JSON मनुष्यों के लिए पढ़ना आसान हो। Miniify सभी अनावश्यक रिक्त स्थान और लाइन ब्रेक को हटा देता है ताकि JSON भेजने या संग्रहीत करने के लिए जितना संभव हो उतना छोटा हो।
मेरा JSON पिछली अल्पविराम त्रुटि के साथ विफल क्यों होता है?
सख्त JSON किसी ऑब्जेक्ट या सरणी में अंतिम आइटम के बाद अल्पविराम की अनुमति नहीं देता है। उस अंतिम अल्पविराम को हटा दें और JSON पार्स हो जाएगा।
क्या मैं JSON में सिंगल कोट्स का उपयोग कर सकता हूँ?
नहीं, JSON स्ट्रिंग्स और कुंजियों में दोहरे उद्धरण चिह्नों का उपयोग होना चाहिए। सिंगल कोट्स जावास्क्रिप्ट कोड में काम करते हैं, लेकिन वे मान्य JSON नहीं हैं और यह टूल उन्हें सही ढंग से अस्वीकार कर देगा।
क्या मेरा JSON डेटा कहीं संग्रहीत या भेजा गया है?
नहीं, फ़ॉर्मेटिंग और सत्यापन पूरी तरह से आपके ब्राउज़र में चलता है, इसलिए आपका डेटा कभी भी आपके डिवाइस को नहीं छोड़ता है।
क्या फ़ॉर्मेटिंग से मेरा डेटा बदल जाता है?
नहीं, फ़ॉर्मेटिंग और छोटा करने से केवल रिक्ति और लाइन ब्रेक बदलते हैं। जब तक JSON प्रारंभ में वैध था, तब तक मान, कुंजियाँ और संरचना बिल्कुल वैसी ही रहती हैं।
