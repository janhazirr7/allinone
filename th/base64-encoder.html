วิธีใช้เครื่องเข้ารหัส Base64

  1. ป้อนข้อความของคุณพิมพ์หรือวางข้อความธรรมดาเพื่อเข้ารหัส หรือวางสตริง Base64 เพื่อถอดรหัส
  2. เลือกเข้ารหัสหรือถอดรหัสกดเข้ารหัสเพื่อเปลี่ยนข้อความเป็น Base64 หรือถอดรหัสเพื่อเปลี่ยน Base64 กลับเป็นข้อความที่อ่านได้
  3. ตรวจสอบข้อผิดพลาดถ้ามีBase64 ที่ไม่ถูกต้องแสดงข้อผิดพลาดที่เป็นมิตรอธิบายปัญหา แทนที่จะเป็นผลลัพธ์ว่างเปล่าหรือที่ผิดเพี้ยน
  4. คัดลอกผลลัพธ์ใช้คัดลอกผลลัพธ์เพื่อนำผลลัพธ์ไปยังอีเมล ไฟล์ตั้งค่า คำขอ API หรือข้อความ

Base64 คืออะไรและทำไมมันจึงมีอยู่

Base64 เป็นวิธีแสดงไบต์ใดๆ รวมถึงข้อความ รูปภาพ และไฟล์ โดยใช้เพียง 64 อักขระที่ปลอดภัย: ตัวอักษรพิมพ์ใหญ่และพิมพ์เล็ก ตัวเลข เครื่องหมายบวกและเครื่องหมายทับ โดยมีเครื่องหมายเท่ากับเป็นส่วนเติมเต็มที่ท้าย คอมพิวเตอร์มักต้องการส่งข้อมูลไบนารีผ่านระบบที่จัดการข้อความธรรมดาได้อย่างปลอดภัยเท่านั้น เช่น ส่วนหัวอีเมล ที่อยู่เว็บ ฟิลด์ JSON และไฟล์ตั้งค่า ไบต์ดิบในที่เหล่านั้นอาจเสียหาย อ่านผิด หรือถูกปฏิเสธ ดังนั้น Base64 จึงแปลมันเป็นข้อความที่รอดจากการเดินทางโดยไม่เปลี่ยนแปลง การแลกเปลี่ยนคือขนาด: ผลลัพธ์ Base64 ใหญ่กว่าข้อมูลเดิมประมาณหนึ่งในสาม เพราะสามไบต์กลายเป็นสี่อักขระ เรื่องนี้ยอมรับได้สำหรับโทเค็น รูปภาพขนาดเล็ก และสตริงสั้น แต่สิ้นเปลืองสำหรับไฟล์ใหญ่มาก นั่นคือเหตุผลที่ Base64 ไม่ใช้สำหรับการสตรีมวิดีโอหรือการดาวน์โหลดขนาดใหญ่

ทำไม Unicode จึงต้องการการดูแลพิเศษ

บักทั่วไปในเครื่องมือ Base64 แบบง่ายคือมันเสียกับข้อความที่ไม่ใช่ภาษาอังกฤษ ฟังก์ชันเบราว์เซอร์เก่า btoa และ atob จัดการเฉพาะอักขระละติน ดังนั้นคำอย่าง café ชื่อในภาษาอูรดูหรือกรีก หรืออิโมจิสามารถให้ข้อผิดพลาดหรือขยะได้ เครื่องมือนี้หลีกเลี่ยงบักนั้นอย่างสมบูรณ์โดยแปลงข้อความของคุณเป็นไบต์ UTF-8 ก่อนด้วย TextEncoder เข้ารหัสไบต์เหล่านั้น และกลับกระบวนการด้วย TextDecoder ในการถอดรหัส นั่นหมายความว่า Hola, Καλημέρα, مرحبا และอิโมจิยิ้มล้วนไปกลับได้อย่างถูกต้อง: เข้ารหัสมัน ถอดรหัสผลลัพธ์ แล้วคุณจะได้ข้อความเดิมทุกประการกลับมา ถ้าเครื่องมืออื่นให้อักขระที่เสียสำหรับข้อความที่มีเครื่องหมายกำกับเสียงหรือไม่ใช่ละติน มันเกือบแน่นอนว่าใช้ btoa และ atob แบบเปลือยโดยไม่มีการจัดการ UTF-8 และคุณควรเปลี่ยนไปใช้เครื่องมือที่ปลอดภัยกับ Unicode อย่างเครื่องมือนี้

การใช้ทั่วไปและคำเตือนด้านความปลอดภัย

  • Data URL: รูปภาพและไอคอนขนาดเล็กมักฝังโดยตรงในหน้าเว็บเป็น Base64 ดังนั้นหน้าเพจจึงไม่ต้องการไฟล์รูปภาพแยกต่างหาก
  • โทเค็น API และการยืนยันตัวตนพื้นฐาน: ชื่อผู้ใช้ รหัสผ่าน และโทเค็นบางครั้งถูกเข้ารหัส Base64 ในส่วนหัว แต่นี่ไม่ใช่การเข้ารหัสและต้องเดินทางผ่าน HTTPS เสมอ
  • ไฟล์แนบอีเมล: ระบบอีเมลเข้ารหัสไฟล์แนบเป็น Base64 เพื่อให้ไฟล์ไบนารีเดินทางผ่านเซิร์ฟเวอร์เมลที่รับเฉพาะข้อความได้
  • การตั้งค่าและการทดสอบ: นักพัฒนาเข้ารหัสสตริงสั้นเพื่อทดสอบ API เก็บข้อมูลก้อนเล็กใน JSON และเปรียบเทียบค่าโดยไม่กังวลเกี่ยวกับอักขระพิเศษ

ความเป็นส่วนตัวและข้อจำกัด

Base64 คือการเข้ารหัส ไม่ใช่การเข้ารหัสลับ ใครก็ตามที่เห็นสตริง Base64 สามารถถอดรหัสได้ในไม่กี่วินาที ดังนั้นอย่าใช้มันเพื่อซ่อนรหัสผ่าน คีย์ลับ หรือข้อมูลส่วนตัว และอย่าถือว่ามันปลอดภัย เครื่องมือนี้ทำงานในเบราว์เซอร์ของคุณทั้งหมด ข้อความของคุณจึงไม่เคยถูกอัปโหลดหรือเก็บไว้ แต่ผลลัพธ์เองยังคงอ่านได้โดยใครก็ตามที่คุณแชร์กับมัน เครื่องมือยอมรับ Base64 มาตรฐานและตัวแปรที่ปลอดภัยกับ URL ที่ใช้เครื่องหมายลบและขีดล่างแทนเครื่องหมายบวกและเครื่องหมายทับ และมันทนต่อการขึ้นบรรทัดใหม่และส่วนเติมเต็มที่หายไป ซึ่งทำให้มันให้อภัยกับสตริงที่คัดลอกจากอีเมล ข้อมูลป้อนที่ใหญ่มากอาจช้าในแท็บเบราว์เซอร์ ดังนั้นสำหรับไฟล์หลายเมกะไบต์ ให้ใช้เครื่องมือเดสก์ท็อปแทน

คำถามที่พบบ่อย

Base64 คือการเข้ารหัสลับหรือไม่?
ไม่ Base64 เป็นเพียงการเข้ารหัส การเปลี่ยนรูปแบบที่ย้อนกลับได้ ใครก็สามารถถอดรหัสสตริง Base64 ได้ทันที ดังนั้นมันจึงต้องไม่ใช้เพื่อซ่อนรหัสผ่านหรือความลับ
ทำไมข้อความที่มีเครื่องหมายกำกับเสียงของฉันจึงเสียในเครื่องมือ Base64 บางตัว?
เครื่องมือเหล่านั้นใช้ btoa และ atob แบบเปลือย ซึ่งจัดการเฉพาะอักขระละติน เครื่องมือนี้แปลงข้อความเป็นไบต์ UTF-8 ก่อน ดังนั้นตัวอักษรที่มีเครื่องหมายกำกับเสียง กรีก อูรดู และอิโมจิจึงทำงานถูกต้องทั้งหมด
ทำไมผลลัพธ์ Base64 จึงยาวกว่าข้อความของฉัน?
Base64 เปลี่ยนทุก 3 ไบต์เป็น 4 อักขระ ดังนั้นผลลัพธ์จึงใหญ่กว่าประมาณ 33 เปอร์เซ็นต์ นั่นคือราคาปกติของการทำให้ข้อมูลไบนารีปลอดภัยสำหรับระบบข้อความเท่านั้น
เครื่องหมายเท่ากับที่ท้ายมีไว้เพื่ออะไร?
เครื่องหมายเท่ากับคือส่วนเติมเต็ม มันเติมกลุ่มสุดท้ายให้เป็นสี่อักขระเมื่อความยาวข้อมูลป้อนไม่ใช่พหุคูณของสาม เพื่อให้ตัวถอดรหัสรู้อย่างแน่ชัดว่าข้อมูลสิ้นสุดที่ใด
ข้อความของฉันถูกส่งไปยังเซิร์ฟเวอร์หรือไม่?
ไม่ การเข้ารหัสและการถอดรหัสทำงานในเบราว์เซอร์ของคุณทั้งหมดและไม่มีสิ่งใดที่คุณป้อนออกจากอุปกรณ์ของคุณ
