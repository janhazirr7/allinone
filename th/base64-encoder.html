วิธีใช้ตัวเข้ารหัส Base64

  1. ป้อนข้อความของคุณพิมพ์หรือวางข้อความธรรมดาเพื่อเข้ารหัส หรือวางสตริง Base64 เพื่อถอดรหัส
  2. เลือกเข้ารหัสหรือถอดรหัสกด Encode เพื่อเปลี่ยนข้อความให้เป็น Base64 หรือ Decode เพื่อเปลี่ยน Base64 กลับเป็นข้อความที่อ่านได้
  3. ตรวจสอบข้อผิดพลาดหากมีBase64 ไม่ถูกต้องแสดงข้อผิดพลาดที่เป็นมิตรซึ่งอธิบายปัญหา แทนที่จะเป็นผลลัพธ์ที่ว่างเปล่าหรืออ่านไม่ออก
  4. คัดลอกผลลัพธ์ใช้ Copy Output เพื่อนำผลลัพธ์ไปไว้ในอีเมล ไฟล์กำหนดค่า คำขอ API หรือข้อความ

Base64 คืออะไรและทำไมจึงมีอยู่

Base64 เป็นวิธีการแสดงไบต์ใดๆ รวมถึงข้อความ รูปภาพ และไฟล์ โดยใช้อักขระที่ปลอดภัยเพียง 64 ตัวเท่านั้น ได้แก่ ตัวพิมพ์ใหญ่และตัวอักษรตัวเล็ก ตัวเลข เครื่องหมายบวกและเครื่องหมายทับ โดยมีเครื่องหมายเท่ากับเป็นส่วนเสริมที่ส่วนท้าย คอมพิวเตอร์มักจำเป็นต้องส่งข้อมูลไบนารี่ผ่านระบบที่จัดการเฉพาะข้อความธรรมดาอย่างปลอดภัย เช่น ส่วนหัวของอีเมล ที่อยู่เว็บ ฟิลด์ JSON และไฟล์การกำหนดค่า ไบต์ดิบในตำแหน่งเหล่านั้นอาจเสียหาย อ่านผิด หรือถูกปฏิเสธ ดังนั้น Base64 จึงแปลไบต์เหล่านั้นเป็นข้อความที่คงอยู่ในการเดินทางโดยไม่มีการเปลี่ยนแปลง ข้อเสียคือขนาด: เอาต์พุต Base64 มีขนาดใหญ่กว่าข้อมูลดั้งเดิมประมาณหนึ่งในสาม เนื่องจากไบต์สามไบต์กลายเป็นอักขระสี่ตัว ซึ่งเป็นที่ยอมรับสำหรับโทเค็น รูปภาพขนาดเล็ก และสตริงสั้นๆ แต่จะสิ้นเปลืองสำหรับไฟล์ขนาดใหญ่มาก ซึ่งเป็นเหตุผลว่าทำไม Base64 จึงไม่ใช้สำหรับสตรีมวิดีโอหรือดาวน์โหลดขนาดใหญ่

เหตุใด Unicode จึงต้องการการดูแลเป็นพิเศษ

จุดบกพร่องทั่วไปในเครื่องมือ Base64 ทั่วไปคือ ข้อผิดพลาดดังกล่าวทำให้ข้อความที่ไม่ใช่ภาษาอังกฤษเสียหาย เบราว์เซอร์รุ่นเก่าฟังก์ชัน btoa และ atob รองรับเฉพาะอักขระละติน ดังนั้นคำเช่น คาเฟ่ ชื่อในภาษาอูรดูหรือกรีก หรืออีโมจิ อาจทำให้เกิดข้อผิดพลาดหรือขยะได้ เครื่องมือนี้หลีกเลี่ยงจุดบกพร่องนั้นโดยสิ้นเชิงโดยการแปลงข้อความของคุณเป็นไบต์ UTF-8 ด้วย TextEncoder ก่อน เข้ารหัสไบต์เหล่านั้น และย้อนกลับกระบวนการด้วย TextDecoder ในการถอดรหัส นั่นหมายถึง Hola, Καγημέρα, مرحبا และอิโมจิยิ้มไปกลับอย่างถูกต้อง: เข้ารหัส ถอดรหัสผลลัพธ์ แล้วคุณจะได้ข้อความต้นฉบับกลับมาทุกประการ หากเครื่องมืออื่นให้อักขระที่ใช้งานไม่ได้สำหรับข้อความที่มีการเน้นเสียงหรือไม่ใช่ภาษาละติน เครื่องมือนั้นเกือบจะใช้ btoa และ atob แบบเปลือยโดยไม่มีการจัดการ UTF-8 และคุณควรเปลี่ยนไปใช้เครื่องมือที่ปลอดภัยสำหรับ Unicode เช่นนี้

การใช้งานทั่วไปและคำเตือนด้านความปลอดภัย

  • URL ข้อมูล: รูปภาพและไอคอนขนาดเล็กมักจะฝังอยู่ในหน้าเว็บโดยตรงในรูปแบบ Base64 ดังนั้นหน้าเว็บจึงไม่จำเป็นต้องมีไฟล์รูปภาพแยกต่างหาก
  • โทเค็น API และการตรวจสอบสิทธิ์พื้นฐาน: บางครั้งชื่อผู้ใช้ รหัสผ่าน และโทเค็นอาจมีการเข้ารหัส Base64 ในส่วนหัว แต่นี่ไม่ใช่การเข้ารหัสและจะต้องเดินทางผ่าน HTTPS เสมอ
  • ไฟล์แนบอีเมล: ระบบอีเมลเข้ารหัสไฟล์แนบใน Base64 เพื่อให้ไฟล์ไบนารีสามารถเดินทางผ่านเซิร์ฟเวอร์เมลแบบข้อความเท่านั้น
  • การกำหนดค่าและการทดสอบ: นักพัฒนาเข้ารหัสสตริงสั้นเพื่อทดสอบ API จัดเก็บ Blob ขนาดเล็กใน JSON และเปรียบเทียบค่าโดยไม่ต้องกังวลกับอักขระพิเศษ

ความเป็นส่วนตัวและข้อจำกัด

Base64 เป็นการเข้ารหัส ไม่ใช่การเข้ารหัส ใครก็ตามที่เห็นสตริง Base64 จะสามารถถอดรหัสได้ภายในไม่กี่วินาที ดังนั้นอย่าใช้เพื่อซ่อนรหัสผ่าน รหัสลับ หรือข้อมูลส่วนตัว และอย่าถือว่าข้อมูลนั้นปลอดภัย เครื่องมือนี้ทำงานทั้งหมดในเบราว์เซอร์ของคุณ ดังนั้นข้อความของคุณจะไม่ถูกอัพโหลดหรือจัดเก็บ แต่ผลลัพธ์นั้นยังคงสามารถอ่านได้โดยทุกคนที่คุณแบ่งปันด้วย เครื่องมือนี้ยอมรับ Base64 มาตรฐานและตัวแปรที่ปลอดภัยต่อ URL ซึ่งใช้เครื่องหมายลบและขีดล่างแทนเครื่องหมายบวกและเครื่องหมายสแลช และทนต่อการขึ้นบรรทัดใหม่และช่องว่างภายในที่หายไป ซึ่งทำให้ให้อภัยกับสตริงที่คัดลอกมาจากอีเมล อินพุตขนาดใหญ่มากอาจช้าในแท็บเบราว์เซอร์ ดังนั้นสำหรับไฟล์ที่มีขนาดหลายเมกะไบต์ ให้ใช้เครื่องมือเดสก์ท็อปแทน

คำถามที่พบบ่อย (FAQ)

การเข้ารหัส Base64 คืออะไร?
ไม่ Base64 เป็นเพียงการเข้ารหัส ซึ่งเป็นการเปลี่ยนแปลงรูปแบบที่ย้อนกลับได้ ใครๆ ก็สามารถถอดรหัสสตริง Base64 ได้ทันที ดังนั้นจึงห้ามใช้เพื่อซ่อนรหัสผ่านหรือความลับเด็ดขาด
เหตุใดข้อความที่มีการเน้นเสียงของฉันจึงแตกในเครื่องมือ Base64 บางตัว
เครื่องมือเหล่านั้นใช้ btoa และ atob เปล่าซึ่งรองรับเฉพาะอักขระละตินเท่านั้น เครื่องมือนี้จะแปลงข้อความเป็นไบต์ UTF-8 ก่อน ดังนั้นตัวอักษรเน้นเสียง ภาษากรีก ภาษาอูรดู และอีโมจิจึงทำงานได้อย่างถูกต้อง
เหตุใดเอาต์พุต Base64 จึงยาวกว่าข้อความของฉัน
Base64 จะเปลี่ยนทุกๆ 3 ไบต์ให้เป็น 4 อักขระ ดังนั้นเอาต์พุตจึงใหญ่ขึ้นประมาณ 33 เปอร์เซ็นต์ นั่นคือราคาปกติของการทำให้ข้อมูลไบนารีปลอดภัยสำหรับระบบแบบข้อความเท่านั้น
เครื่องหมายเท่ากับท้ายมีไว้เพื่ออะไร?
เครื่องหมายเท่ากับคือช่องว่างภายใน โดยจะเติมกลุ่มสุดท้ายให้มีอักขระสี่ตัวเมื่อความยาวอินพุตไม่หารด้วยสาม ดังนั้นตัวถอดรหัสจึงรู้แน่ชัดว่าข้อมูลสิ้นสุดที่ใด
ข้อความของฉันถูกส่งไปยังเซิร์ฟเวอร์หรือไม่?
ไม่ การเข้ารหัสและถอดรหัสจะทำงานทั้งหมดในเบราว์เซอร์ของคุณ และไม่มีอะไรที่คุณป้อนไปจากอุปกรณ์ของคุณ
