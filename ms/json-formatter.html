Cara Menggunakan Pemformat JSON

  1. Tampal JSON andaSalin JSON daripada API, fail konfigurasi atau tutorial dan tampal ia ke dalam kotak besar.
  2. Pilih tindakanTekan Format untuk menjadikannya mudah dibaca dengan inden, Kecilkan untuk mengecilkannya kepada satu baris, atau Sahkan Sahaja untuk menyemaknya tanpa mengubahnya.
  3. Baca ralat jika adaJika JSON tidak sah, alat menunjukkan ralat tepat daripada penghuraian dalam kata mudah, jadi anda tahu apa yang perlu dibetulkan.
  4. Salin keputusanGunakan Salin Output untuk membawa JSON yang diformat atau dikecilkan kembali kepada kod, konfigurasi atau alat API anda.

Apakah JSON dan Mengapa Pemformatan Penting

JSON, singkatan untuk JavaScript Object Notation, ialah cara paling lazim komputer bertukar data berstruktur di web. API, fail konfigurasi dan banyak aplikasi semuanya bertutur JSON kerana ia mudah dibaca dan mudah dihuraikan oleh mesin. Dokumen JSON yang sah dibina daripada objek dalam kurungan kerinting, tatasusunan dalam kurungan segi empat, rentetan dalam tanda petik berganda, nombor, dan nilai true, false dan null. Pemformatan tidak mengubah maksud data, tetapi ia mengubah betapa mudahnya ia dibaca oleh manusia. JSON yang dikecilkan, dengan semua ruang dibuang, lebih kecil dan lebih pantas dihantar melalui rangkaian, justeru API menggunakannya, tetapi ia hampir mustahil untuk dibaca atau dinyahpepijat. JSON yang dicantikkan, dengan inden dua ruang dan satu nilai setiap baris, lebih besar tetapi membolehkan anda mengesan koma yang hilang atau kurungan yang salah dalam beberapa saat.

Ralat JSON Paling Lazim

  • Koma yang hilang atau berlebihan: setiap item dalam objek atau tatasusunan kecuali yang terakhir memerlukan koma, dan koma tertinggal selepas item terakhir tidak dibenarkan dalam JSON ketat.
  • Tanda petik tunggal dan bukannya tanda petik berganda: rentetan JSON mesti menggunakan tanda petik berganda, walaupun kod JavaScript sering membenarkan tanda petik tunggal.
  • Kunci tidak dipetik: kunci objek mesti rentetan yang dipetik, jadi {name: "Ana"} adalah tidak sah dan mesti {"name": "Ana"}.
  • Komen: JSON tidak membenarkan komen, jadi baris yang bermula dengan // akan memecahkan penghuraian walaupun ia kelihatan tidak berbahaya.
  • Teks tertinggal atau berbilang dokumen: menampal dua objek JSON satu demi satu adalah tidak sah; balut ia dalam tatasusunan atau betulkan satu demi satu.

Pemformatan lawan Pengecilan: Bila Menggunakan Setiap Satu

Gunakan Format apabila anda membaca, menyahpepijat atau belajar daripada JSON, kerana inden mendedahkan struktur sepintas lalu dan menjadikan sarang jelas. Gunakan Kecilkan apabila anda perlu menampal JSON ke dalam URL, medan konfigurasi padat, permintaan ujian atau mesej di mana saiz penting dan kebolehbacaan tidak. Gunakan Sahkan Sahaja apabila anda hanya memerlukan jawapan ya atau tidak, sebagai contoh sebelum menyimpan fail konfigurasi, kerana ia menyemak JSON tanpa menggantikan teks asal anda. Dalam ketiga-tiga kes alat mula-mula menghuraikan JSON, jadi keputusan yang dikecilkan atau diformat dijamin sah; jika penghuraian gagal, anda mendapat ralat dan bukannya output yang rosak secara senyap, yang tepat apa yang anda mahu sebelum menghantar kod.

Privasi dan Had

Pemformat ini berjalan sepenuhnya dalam pelayar anda. JSON anda tidak pernah dimuat naik, dilog atau dikongsi, yang penting kerana JSON sering mengandungi kunci API, data peribadi atau konfigurasi dalaman. Jangan sekali-kali menampal rahsia ke dalam mana-mana pemformat dalam talian yang anda tidak percayai, dan putarkan mana-mana kunci yang anda dedahkan secara tidak sengaja. Alat mengendalikan respons API biasa dan fail konfigurasi dengan mudah, tetapi dokumen yang sangat besar, berpuluh-puluh megabait, mungkin perlahan dalam tab pelayar kerana penghuraian dan penukaran semula kepada rentetan mengambil memori. Ia juga mengikut peraturan JSON yang ketat, jadi ia akan menolak tambahan gaya JavaScript seperti koma tertinggal, tanda petik tunggal dan komen, walaupun sesetengah alat menerimanya secara longgar.

Soalan Lazim (FAQ)

Apakah perbezaan antara Format dan Kecilkan?
Format menambah inden dan pemisah baris supaya JSON mudah dibaca oleh manusia. Kecilkan membuang semua ruang dan pemisah baris yang tidak perlu supaya JSON sekecil mungkin untuk dihantar atau disimpan.
Mengapakah JSON saya gagal dengan ralat koma tertinggal?
JSON ketat tidak membenarkan koma selepas item terakhir dalam objek atau tatasusunan. Buang koma akhir itu dan JSON akan dihuraikan.
Bolehkah saya menggunakan tanda petik tunggal dalam JSON?
Tidak. Rentetan dan kunci JSON mesti menggunakan tanda petik berganda. Tanda petik tunggal berfungsi dalam kod JavaScript, tetapi ia bukan JSON yang sah dan alat ini akan menolaknya dengan betul.
Adakah data JSON saya disimpan atau dihantar ke mana-mana?
Tidak. Pemformatan dan pengesahan berjalan sepenuhnya dalam pelayar anda, jadi data anda tidak pernah keluar dari peranti anda.
Adakah pemformatan mengubah data saya?
Tidak. Pemformatan dan pengecilan hanya mengubah jarak dan pemisah baris. Nilai, kunci dan struktur kekal tepat sama, selagi JSON itu sah pada mulanya.
