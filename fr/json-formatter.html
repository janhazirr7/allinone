Comment utiliser le formateur JSON

  1. Collez votre JSONCopiez du JSON depuis une API, un fichier de configuration ou un tutoriel et collez-le dans le grand champ.
  2. Choisissez une actionAppuyez sur Formater pour le rendre lisible avec une indentation, sur Minifier pour le réduire à une ligne, ou sur Valider seulement pour le vérifier sans le modifier.
  3. Lisez l'erreur s'il y en a uneSi le JSON est invalide, l'outil affiche l'erreur exacte de l'analyseur en termes simples, vous savez donc quoi corriger.
  4. Copiez le résultatUtilisez « Copier la sortie » pour reprendre le JSON formaté ou minifié dans votre code, votre configuration ou votre outil API.

Ce qu'est le JSON et pourquoi le formatage compte

JSON, abréviation de JavaScript Object Notation, est la façon la plus courante dont les ordinateurs échangent des données structurées sur le web. Les API, les fichiers de configuration et de nombreuses applications parlent toutes JSON car il est simple à lire et facile à analyser pour les machines. Un document JSON valide est construit à partir d'objets entre accolades, de tableaux entre crochets, de chaînes entre guillemets doubles, de nombres, et des valeurs true, false et null. Le formatage ne change pas ce que signifient les données, mais il change la facilité avec laquelle un humain peut les lire. Le JSON minifié, avec tous les espaces supprimés, est plus petit et plus rapide à envoyer sur un réseau, c'est pourquoi les API l'utilisent, mais il est presque impossible à lire ou à déboguer. Le JSON embelli, avec une indentation de deux espaces et une valeur par ligne, est plus grand mais vous permet de repérer une virgule manquante ou un crochet erroné en quelques secondes.

Les erreurs JSON les plus courantes

  • Virgules manquantes ou en trop : chaque élément d'un objet ou d'un tableau, sauf le dernier, a besoin d'une virgule, et une virgule finale après le dernier élément n'est pas autorisée en JSON strict.
  • Guillemets simples au lieu de guillemets doubles : les chaînes JSON doivent utiliser des guillemets doubles, même si le code JavaScript autorise souvent les guillemets simples.
  • Clés sans guillemets : les clés d'objet doivent être des chaînes entre guillemets, donc {name: "Ana"} est invalide et doit être {"name": "Ana"}.
  • Commentaires : le JSON n'autorise pas les commentaires, les lignes commençant par // casseront donc l'analyse même si elles semblent inoffensives.
  • Texte final ou documents multiples : coller deux objets JSON l'un après l'autre est invalide ; enveloppez-les dans un tableau ou corrigez-les un par un.

Formater contre minifier : quand utiliser chacun

Utilisez Formater quand vous lisez, déboguez ou apprenez à partir de JSON, car l'indentation révèle la structure d'un coup d'œil et rend l'imbrication évidente. Utilisez Minifier quand vous devez coller du JSON dans une URL, un champ de configuration compact, une requête de test ou un message où la taille compte et la lisibilité non. Utilisez Valider seulement quand vous avez juste besoin d'une réponse oui ou non, par exemple avant d'enregistrer un fichier de configuration, car cela vérifie le JSON sans remplacer votre texte d'origine. Dans les trois cas, l'outil analyse d'abord le JSON, un résultat minifié ou formaté est donc garanti valide ; si l'analyse échoue, vous obtenez une erreur au lieu d'une sortie silencieusement cassée, ce qui est exactement ce que vous voulez avant de livrer du code.

Confidentialité et limites

Ce formateur fonctionne entièrement dans votre navigateur. Votre JSON n'est jamais téléversé, journalisé ou partagé, ce qui compte car le JSON contient souvent des clés API, des données personnelles ou de la configuration interne. Ne collez jamais de secrets dans un formateur en ligne en qui vous n'avez pas confiance, et renouvelez toute clé que vous exposez accidentellement. L'outil gère facilement les réponses d'API et les fichiers de configuration typiques, mais les documents extrêmement volumineux, de dizaines de mégaoctets, peuvent être lents dans un onglet de navigateur car les analyser et les re-sérialiser prend de la mémoire. Il suit aussi des règles JSON strictes, il rejettera donc les extras de style JavaScript comme les virgules finales, les guillemets simples et les commentaires, même si certains outils les acceptent avec indulgence.

Questions fréquemment posées (FAQ)

Quelle est la différence entre Formater et Minifier ?
Formater ajoute une indentation et des sauts de ligne pour que le JSON soit facile à lire pour les humains. Minifier supprime tous les espaces et sauts de ligne inutiles pour que le JSON soit aussi petit que possible pour l'envoi ou le stockage.
Pourquoi mon JSON échoue-t-il avec une erreur de virgule finale ?
Le JSON strict n'autorise pas de virgule après le dernier élément d'un objet ou d'un tableau. Retirez cette virgule finale et le JSON s'analysera.
Puis-je utiliser des guillemets simples en JSON ?
Non. Les chaînes et les clés JSON doivent utiliser des guillemets doubles. Les guillemets simples fonctionnent dans le code JavaScript, mais ils ne sont pas du JSON valide et cet outil les rejettera correctement.
Mes données JSON sont-elles stockées ou envoyées quelque part ?
Non. Le formatage et la validation s'exécutent entièrement dans votre navigateur, vos données ne quittent donc jamais votre appareil.
Le formatage change-t-il mes données ?
Non. Le formatage et la minification ne changent que les espacements et les sauts de ligne. Les valeurs, les clés et la structure restent exactement les mêmes, tant que le JSON était valide au départ.
