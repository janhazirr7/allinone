Comment utiliser le formateur JSON

  1. Collez votre JSONCopiez le JSON depuis une API, un fichier de configuration ou un tutoriel et collez-le dans la grande boîte.
  2. Choisissez une actionAppuyez sur Format pour le rendre lisible avec indentation, Réduire pour le réduire à une ligne ou Valider uniquement pour le vérifier sans le modifier.
  3. Lisez l'erreur s'il y en a uneSi le JSON n'est pas valide, l'outil affiche l'erreur exacte de l'analyseur en termes simples, afin que vous sachiez quoi corriger.
  4. Copiez le résultatUtilisez Copy Output pour récupérer le JSON formaté ou minifié dans votre code, votre configuration ou votre outil API.

Qu'est-ce que JSON et pourquoi le formatage est important

JSON, abréviation de JavaScript Object Notation, est le moyen le plus courant pour les ordinateurs d'échanger des données structurées sur le Web. Les API, les fichiers de configuration et de nombreuses applications parlent tous JSON car il est simple à lire et facile à analyser pour les machines. Un document JSON valide est construit à partir d'objets entre accolades, de tableaux entre crochets, de chaînes entre guillemets doubles, de nombres et des valeurs true, false et null. Le formatage ne change pas la signification des données, mais il modifie la facilité de lecture pour un humain. Le JSON minifié, sans tous les espaces, est plus petit et plus rapide à envoyer sur un réseau, c'est pourquoi les API l'utilisent, mais il est presque impossible à lire ou à déboguer. JSON embelli, avec une indentation à deux espaces et une valeur par ligne, est plus grand mais vous permet de repérer une virgule manquante ou une parenthèse erronée en quelques secondes.

Les erreurs JSON les plus courantes

  • Virgules manquantes ou supplémentaires : chaque élément d'un objet ou d'un tableau, à l'exception du dernier, a besoin d'une virgule, et une virgule après le dernier élément n'est pas autorisée en JSON strict.
  • Guillemets simples au lieu de guillemets doubles : les chaînes JSON doivent utiliser des guillemets doubles, même si le code JavaScript autorise souvent les guillemets simples.
  • Clés sans guillemets : les clés d'objet doivent être des chaînes entre guillemets, donc {name : "Ana"} n'est pas valide et doit être {"name": "Ana"}.
  • Commentaires : JSON n'autorise pas les commentaires, donc les lignes commençant par // interrompront l'analyse même si elles semblent inoffensives.
  • Texte de fin ou plusieurs documents : coller deux objets JSON l'un après l'autre n'est pas valide ; enveloppez-les dans un tableau ou corrigez-les un par un.

Formatage ou réduction : quand les utiliser ?

Utilisez Format lorsque vous lisez, déboguez ou apprenez à partir de JSON, car l'indentation révèle la structure en un coup d'œil et rend l'imbrication évidente. Utilisez Minify lorsque vous devez coller du JSON dans une URL, un champ de configuration compact, une demande de test ou un message où la taille compte et la lisibilité ne compte pas. Utilisez Validate Only lorsque vous n'avez besoin que d'une réponse par oui ou par non, par exemple avant d'enregistrer un fichier de configuration, car il vérifie le JSON sans remplacer votre texte d'origine. Dans les trois cas, l'outil analyse d'abord le JSON, de sorte qu'un résultat minifié ou formaté est garanti comme étant valide ; si l'analyse échoue, vous obtenez une erreur au lieu d'une sortie interrompue silencieusement, ce qui est exactement ce que vous souhaitez avant d'expédier le code.

Confidentialité et limites

Ce formateur s'exécute entièrement dans votre navigateur. Votre JSON n'est jamais téléchargé, enregistré ou partagé, ce qui est important car JSON contient souvent des clés API, des données personnelles ou une configuration interne. Ne collez jamais de secrets dans un formateur en ligne auquel vous ne faites pas confiance et ne faites pas pivoter les clés que vous exposez accidentellement. L'outil gère facilement les réponses API et les fichiers de configuration typiques, mais les documents extrêmement volumineux, de plusieurs dizaines de mégaoctets, peuvent être lents dans un onglet de navigateur, car leur analyse et leur re-stringification nécessitent de la mémoire. Il suit également des règles JSON strictes, de sorte qu'il rejettera les extras de style JavaScript tels que les virgules finales, les guillemets simples et les commentaires, même si certains outils les acceptent de manière vague.

Foire aux questions (FAQ)

Quelle est la différence entre Formater et Réduire ?
Le format ajoute une indentation et des sauts de ligne afin que JSON soit facile à lire pour les humains. Minify supprime tous les espaces et sauts de ligne inutiles afin que JSON soit aussi petit que possible pour l'envoi ou le stockage.
Pourquoi mon JSON échoue-t-il avec une erreur de virgule finale ?
Le JSON strict n'autorise pas la virgule après le dernier élément d'un objet ou d'un tableau. Supprimez cette dernière virgule et le JSON sera analysé.
Puis-je utiliser des guillemets simples en JSON ?
Non. Les chaînes et clés JSON doivent utiliser des guillemets doubles. Les guillemets simples fonctionnent dans le code JavaScript, mais ils ne sont pas des JSON valides et cet outil les rejettera correctement.
Mes données JSON sont-elles stockées ou envoyées n'importe où ?
Non. Le formatage et la validation s'effectuent entièrement dans votre navigateur, de sorte que vos données ne quittent jamais votre appareil.
Le formatage modifie-t-il mes données ?
Non. Le formatage et la réduction modifient uniquement l'espacement et les sauts de ligne. Les valeurs, les clés et la structure restent exactement les mêmes, tant que le JSON était valide au départ.
